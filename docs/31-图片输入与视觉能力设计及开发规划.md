# 31 图片输入与视觉能力设计及开发规划

> 2026-10-15。实施入口；共享合同唯一来源为 Aether `docs/19-图片输入与视觉能力.md`（类型、上限、协议编码、校验、界面）。本文只写归属、AutoNote 宿主实现、任务顺序和验收。完成状态以第 6 节实际证据为准。

## 1. 用户决定（2026-10-15）

1. 模型能否看图在**配置时**确定（推断 + 用户开关），参考 Cherry；发送时不猜、不做 OCR。
2. 不考虑 token 预算：图片不估算、不因预算裁剪。
3. 图片**临时保存 7 天**再定期清理：保留期内历史显示、重新生成、@换模型、追问都带原图；过期后显示“图片已过期”，重新生成只发文字。

## 3. Web 宿主实现

- 请求：`RunRequestSchema` 增 `images`（zod 同 Aether 上限）；`/runs` 继续用 `JSON_BODY_LIMITS.note`（≈12 MiB，4×4 MiB base64 后 ≈21 MiB 超限）→ 新增 `JSON_BODY_LIMITS.run = 24 MiB`。
- 存储：R2 键 `ai-images/<userId>/<sourceTurnId>/<idx>`；D1 `ai_turn_images(user_id, turn_id, idx, mime, object_key NULL, created_at, PRIMARY KEY(user_id, turn_id, idx))`，`object_key = NULL` 表示已过期。turn 建立成功后写入；retry/@换模型/fork 新 turn **复制行、共享同一 object_key**（不复制 R2 对象），`created_at` 沿用原图上传时间。不计入笔记附件配额（7 天自动清理，单轮上限 16 MiB，受现有每用户并发槽限制）。
- 编码：`protocol.ts` 的 user content 构造与 Aether §4 表一致；历史 user 消息按 turn 读回图片。
- 读取：`GET /api/ai/kit/conversations/:id/turns/:turnId/images/:idx`，校验所属用户，返回原 MIME 与 `Cache-Control: private, max-age=3600`；过期/不存在 404。`toWire` 生成 `Turn.images[].url`，过期行为 `url: null`。
- 清理：`scheduled()` 加 `purgeExpiredChatImages(env)`：取 `object_key IS NOT NULL AND created_at < now-7d` 的不同 object_key（每批 100），先删 R2 对象，再把引用它的行置 `object_key = NULL`；失败下次重试。删除会话/turn 时删除行，随后删除已无任何行引用的 object_key 对应对象。
- 视觉守卫：`resolveModel` 返回 `canVision`；带图且不支持 → `bad_request{images, vision_unsupported}`。

## 5. 不做

OCR 兜底、图片压缩/缩放、Gemini 协议、PDF/其他文件、供应商文件 API、图片 token 估算、多模型并发。需要时另立任务。
