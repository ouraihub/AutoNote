# 32 生成图片设计及开发规划

> 2026-10-15。共享合同唯一来源：Aether `docs/20-生成图片工具.md`。本文是实施入口、任务与验收；完成状态以第 4 节证据为准。

## 1. 用户决定（2026-10-15）

1. 输入框改为 Cherry 式「+」工具菜单：上传附件、生成图片。
2. 生成图片采用 **对话模型调用 `generate_image` 工具**（同 Cherry），不是单独的图片模式。
3. 绘图接口：OpenAI 兼容 `/v1/images/generations`；绘图模型在“默认模型”中选择（新角色 `painting`）。

## 2. 关键事实

- 桌面已有工具调用循环（Aether Runner + `HostTools`），只需新增内置工具。
- Web Worker 目前**没有工具调用循环**：`StoredMessage.assistant.tool_calls: never[]`，请求不带 `tools`。需先补三协议的工具调用流式解析、回填与多轮（仅宿主内置工具，最多 4 轮），这是本特性最大的工作量。
- 图片存储与 7 天清理复用 docs/31 的设施，仅加 `kind` 区分输入/生成。
