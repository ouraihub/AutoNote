## 2. 通用设计原则

### 2.1 面向接口

- **跨越边界的依赖一律面向接口**。边界包括：界面与持久化之间（`Backend` 端口）、业务与时钟之间、业务与网络之间、业务与事件发送之间、业务与日志之间。
- 接口由**使用方**定义，放在使用方所在的模块里（例如 `packages/app/src/backend/port.ts`），实现方负责去实现。不允许出现"实现方先写好类，使用方再抽取接口"的反向做法。
- 依赖通过**构造参数注入**。状态类和服务类不能在内部 `import` 一个具体实现的单例；只有组合根（composition root，即各宿主的 `main.ts` 或 `lib.rs`）才负责把具体实现装配起来。
- 不做"为了抽象而抽象"。只有一个实现、并且不跨边界的内部模块，不需要接口。判断标准只有一条：测试时要不要替换它？需要替换才定义接口。

### 2.2 面向对象

- **有状态、有行为、有不变量**的东西写成类（TS）或结构体加 `impl`（Rust）。纯变换写成函数，不为了形式包一层类。
- 单一职责：一个类只围绕一个聚合（例如 `NotesState` 负责笔记集合），超过约 400 行就按职责拆分。
- 组合优于继承。TS 类最多继承一层，仅限 `BackendError extends Error` 这类情况；Rust 用 trait 加组合。
- 封装：字段默认是私有的（TS 用 `#field` 或 `private`，Rust 默认私有），对外只暴露只读视图和意图明确的方法，例如 `rename(id, name)`，而不是 `setFolders(list)`。
- 不变量在构造函数和写方法里强制检查，违反时抛 `BackendError('bad_request')` 或返回 `Err`，不要让对象进入非法状态。

### 2.3 模块化

- 每个模块只有一个公开入口：TS 用 `index.ts`，Rust 用 `lib.rs` 或 `mod.rs`，并且只导出对外契约。模块内部的文件不能被外部直接 import，由 eslint `no-restricted-imports` 检查。
- 依赖方向严格单向（见概要设计 §2.1），禁止循环依赖，由 eslint `import/no-cycle` 和 cargo 保证。
- 一个文件只放一个主题：TS 文件不超过约 400 行，Svelte 组件不超过约 250 行，Rust 文件不超过约 600 行（测试代码不计）。超过就拆。这不是机械的上限，但评审时必须给出不拆的理由。

### 2.4 组件化

- **展示组件**只通过 props 接收数据、通过回调 props 向外报告，不读取任何全局状态，也不调用端口，可以在 `/__gallery` 里单独渲染。
- **容器组件**（feature 根组件）从上下文取状态类，把数据和回调传给展示组件，每个 feature 只有一个容器组件。
- 通用基础组件（Button、Dialog、Menu……）放在 `packages/app/src/components/ui/`，业务组件放在 `packages/app/src/features/<feature>/`。基础组件不能引用业务组件。

## 3. 日志规范

### 3.1 共同规则

- **结构化**：每条日志 = 事件名 + 字段。事件名用小写点分，格式 `<模块>.<对象>.<动作>`，例如 `notes.save.failed`、`sync.pull.completed`、`mcp.request.rejected`。字段是扁平的键值对，同一个事件名的字段集合保持固定。
- **级别语义**：

  | 级别    | 什么时候用                                   | 例子                                                  |
  | ------- | -------------------------------------------- | ----------------------------------------------------- |
  | `error` | 操作失败，且需要人处理或会丢数据             | outbox 回放连续失败、数据库迁移失败                   |
  | `warn`  | 操作降级或已自动恢复                         | FTS 回退到 LIKE、WS 断开后改走轮询、409 冲突后 rebase |
  | `info`  | 生命周期和关键业务节点，每个用户操作最多一条 | 启动、同步完成、导入完成、MCP 服务启停                |
  | `debug` | 排查问题用，默认不输出                       | 单条请求耗时、队列长度                                |

- 禁止日志记录正文、标题、附件内容、密码、cookie、完整 token、TOTP 秘钥和备份凭据。凭据字段整项删除或固定写 `[redacted]`，不得保留 token 的首尾片段；只记录资源 ID、长度、状态码及耗时。
- **不在循环里逐条记日志**，改成汇总成一条（`count`、`durationMs`）。
- **每个错误只记一次**：在最终处理它的那一层记。中间层只负责传递错误并补充上下文，不重复记录。

### 3.2 TypeScript（app / 宿主）

- `packages/app/src/log/logger.ts` 定义 `Logger` 接口：`debug | info | warn | error(event: string, fields?: LogFields): void`。它由组合根注入，状态类通过构造参数拿到。
- 除 `Logger` 的具体实现之外，**禁止直接调用 `console.*`**（eslint `no-console: error`）。
- Web 实现：输出到 `console`，同时写进一个 200 条的环形缓冲区，供「设置 → 关于 → 诊断信息」导出。桌面实现：批量调用 `app_log` command 转发给 Rust 的 `tracing`，与 Rust 日志写入同一个日志文件。

### 3.3 Rust

- 统一使用 `tracing`，字段写在宏参数里：`tracing::info!(note_id = %id, rev, "note.save.completed")`。
- 每个 Tauri command 和每个 MCP tool 入口加 `#[tracing::instrument(skip_all, fields(...), err)]`，失败时自动记一条 `error`，其他地方不再重复记。
- 禁止使用 `println!`、`eprintln!`、`dbg!`。唯一例外是日志系统初始化之前的启动失败（`lib.rs` 的 `run()`）。
- 日志在 `data\logs\autonote.log`，写入达到5MiB即轮转，总计最多3个文件（当前+2历史），运行期间也轮转。具体文件句柄与失败处理见21 §7，不将仅启动轮转当完成。

### 3.4 Worker（Hono）

- 新写或改动的 worker 代码通过 `web/src/worker/lib/log.ts` 输出 JSON 行：`console.log(JSON.stringify({ level, event, ...fields }))`，Workers Logs 可以直接按字段检索。
- 已有的 `console.warn('[autonote] …')` 不专门改，只有当任务涉及到那一行时才顺手迁移。

## 4. 异常规范

### 4.1 共同规则

- **错误分成两类**，处理方式完全不同：
  1. **预期错误**：输入非法、未登录、冲突、限流、离线。它们使用概要设计 §5 定义的 `code`，调用方按 `code` 分支处理，最终给用户看的是翻译后的文案（`api.error.<code>`）。
  2. **程序错误**：违反不变量或出现 bug。不针对它们做分支处理，让它们冒泡到错误边界，写一条 `error` 日志并提示通用文案。
- **不吞错误**：每个 `catch` 或 `match Err` 只能做三件事之一：按具体 `code` 处理并恢复；补充上下文后重新抛出；在最终处理的那一层记日志并通知用户。空的 `catch {}` 一律禁止（eslint `no-empty`，同时注释也不能作为豁免理由）。
- **不靠文案判断错误类型**：禁止 `message.includes(...)` 这类判断。唯一的例外是 参考项目 遗留的 `translateServiceMessage`，它只负责把服务端返回的英文文案映射到 i18n 的 key，不参与控制流。
- **输入非法就报错，不猜测**（沿用 AutoBee 概要设计 §4.2）：遇到不认识的枚举值、越界的参数，一律返回 `bad_request`，不擅自回退到某个默认值。

### 4.2 TypeScript

- 跨越端口边界抛出的只能是 `BackendError`（概要设计 §5）。宿主在边界处把原始错误（`Response`、`TypeError: Failed to fetch`、Tauri 返回的错误对象）转换成 `BackendError`，app 层不接触原始错误。
- 只能 `throw` 一个 `Error` 实例，禁止抛出字符串或普通对象。`catch (error)` 里的 `error` 类型是 `unknown`，先用 `isBackendError(error)` 收窄再使用。
- 写入失败按 mutationId 回滚本次乐观元数据；正文编辑缓冲保留供用户恢复。异步持久日志失败由 write 事件报告，不能误回滚后续输入。状态层负责 `notify.error`，避免组件重复 toast。
- `<svelte:boundary>` 负责渲染/相关 effect 异常；事件处理器和异步请求的错误仍必须在状态层处理，不能假设 boundary 会捕获它们。

### 4.3 Rust

- 每个 crate 内部用 `thiserror` 定义自己的错误枚举（例如 `note_core::Error`），变体按失败原因划分，不按调用位置划分。
- 在 IPC/MCP 边界统一转换为 `AppError`。底层路径、SQL 和凭据不得原样进入 details，详细原因只写脱敏日志。
- 非测试代码里禁止使用 `unwrap`、`expect`、`panic!`、`unreachable!`、`todo!`（workspace lints 设为 warn，配合 `clippy -D warnings` 实际等同于 deny）。测试模块用 `#[allow(clippy::unwrap_used, reason = "…")]` 显式豁免。
- 用 `?` 传播错误，需要补充上下文时写 `.map_err(|e| Error::Open { path, source: e })`。库 crate 不使用 `anyhow`。
- `Mutex` 中毒（poisoned）映射为 `internal`，不 panic。

### 4.4 Worker

- 路由中一律 `throw ApiError.*(...)`，由 `app.onError` 统一转换成错误响应（这是现有做法）。不要混用 Hono 的 `HTTPException`。
- 新写的路由在入口处用 `zod`（已是依赖）校验请求体和查询参数，校验失败时返回 `bad_request`，`details` 里放字段路径。已有路由里的手写校验保持不动。

## 5. TypeScript

- 编译选项：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitOverride`、`verbatimModuleSyntax`、`isolatedModules`。其中 `noUncheckedIndexedAccess` 和 `exactOptionalPropertyTypes` 只在 `packages/app` 与各宿主的新代码里开启；worker 和 shared 的原有代码不开，否则会引入几百处与本次改动无关的修改。
- 不用 `any`，改用 `unknown` 再收窄。不在非空断言 `!` 上赌运气：`noUncheckedIndexedAccess` 报出的地方要显式处理 `undefined`。
- 类型定义：数据形状用 `interface`，联合类型和工具类型用 `type`。用标签联合（`kind`/`type` 字段）表示状态机，`switch` 的 default 分支写 `const _exhaustive: never = x` 做穷尽检查。
- 不用 TS `enum`，改用 `as const` 对象加字面量联合，以配合 `verbatimModuleSyntax`。仅作类型使用的导入必须写 `import type`。
- 不可变：函数参数一律不修改。公开的只读视图用 `readonly T[]` / `ReadonlyMap`。
- 异步：所有 Promise 必须 `await` 或显式 `void` 并附注理由（eslint `no-floating-promises`）。可取消的操作接收 `AbortSignal`。
- 命名：类型和类用 PascalCase，变量和函数用 camelCase，常量用 UPPER_SNAKE，文件用 kebab-case（Svelte 组件文件用 PascalCase）。布尔值以 `is`/`has`/`can` 开头。
- 小函数：只有一行、且只是转发调用的包装函数应当内联，除非它满足以下情况之一：是导出的领域概念、有三个以上调用点需要保持一致、是类型守卫，或是依赖注入与测试的接缝。

## 6. Svelte 5

- **只用 runes**：`$state`、`$derived`、`$effect`、`$props`、`$bindable`。禁止使用 Svelte 4 语法：`export let`、`$:`、`on:event`、`<slot>`、`createEventDispatcher`，以及用 `svelte/store` 做状态管理。eslint-plugin-svelte 开启 `svelte/valid-compile`，编译警告一律当错误处理。
- **状态放在 `*.svelte.ts` 的类里**。类字段用 `$state` 或 `$state.raw` 声明，派生值用 `$derived` 字段或 getter。对外暴露只读 getter 和意图明确的方法，组件不直接给字段赋值（§2.2）。
- **大集合用 `$state.raw`**：笔记摘要表、搜索结果这类数据用 `$state.raw` 保存，整体替换，避免对上千条对象做深层代理。只有需要细粒度追踪的小对象才用深层 `$state`。
- `$effect` 用于订阅和 DOM 同步，有资源时返回清理函数。禁止形成读写同一响应式状态的反馈循环；异步加载可以由 effect 调用状态方法，但必须用 AbortSignal 或 generation 丢弃过期结果。`getAbortSignal()` 只在支持的 effect/derived 上下文调用，不在任意回调调用。
- **依赖注入走 context**：每个状态类配一对类型安全的 context，用 `createContext<T>()` 生成 `[get, set]`（Svelte ≥5.40，项目用的是 5.57.1）。组合根调用 `set`，容器组件调用 `get`。不用模块级单例，这样测试和 `/__gallery` 可以各自注入替身。
- **Props**：用 `let { a, b = 1, onChange }: Props = $props()`，`Props` 写成具名 `interface`。回调 prop 命名为 `onXxx`。需要双向绑定时才用 `$bindable`，默认单向传递。
- **内容分发**：用 snippet（`{#snippet}` / `{@render}`），类型写作 `Snippet<[Args]>`。
- **DOM 行为**：可复用的 DOM 行为（点击外部关闭、自动聚焦、调整尺寸）写成 attachment（`{@attach}`），不用 `use:` action。
- **错误边界**：feature 根组件包一层 `<svelte:boundary>`（§4.2）。
- **测试**：状态类在 node 环境中直接 `new` 出来测，注入假的 `Backend`。组件测试用 `@testing-library/svelte` 加 jsdom，只测交互和可访问性，不测样式。

## 7. Tauri 2

- **command 只做转发**：入参反序列化 → 调用 `note-core` 或其他 crate → 转换错误 → 返回。不在 command 里写业务逻辑（概要设计 §2）。
- **全部 command 都是 `async` 的**，同步的 SQLite 调用放进 `tauri::async_runtime::spawn_blocking`，不阻塞 IPC 线程。返回类型固定为 `Result<T, AppError>`。
- **状态**：用 `app.manage()` 注册由 `Arc` 包裹的服务对象，例如 `Library`、`SyncService`、`McpService`。command 通过 `State<'_, T>` 取用。可变部分由服务内部的 `Mutex`/`RwLock` 保护，不把 `Mutex` 直接暴露给 command。
- **事件与流**：一次性的通知用 `app.emit("autonote://…", payload)`。进度这类高频、有序、只发给一个调用方的数据，用 `tauri::ipc::Channel<T>` 作为 command 参数传回，不用全局事件广播。
- **权限最小化**：`capabilities/default.json` 只开放实际用到的权限（概要设计 §8），CSP 保持严格。自定义协议 `autonote-file` 只提供数据目录下 `files/` 里的内容，并校验 ID 格式，防止路径穿越。
- **插件**：只用官方插件（single-instance、window-state、dialog、opener、global-shortcut）。npm 包和 Rust crate 的主版本、次版本必须一致（沿用 AutoBee 的约定），版本号写死。
- Tauri JS 访问统一在 `desktop/src/lib/ipc/transport.ts`（实现适配层）内；其余模块只接收 `IpcTransport` 接口。不要强迫所有端口实现挤在一个文件里。

## 8. Hono 4（只约束新写或改动的 worker 代码，见 §1）

- **类型化的应用**：每个路由模块都导出 `new Hono<AppBindings>()`，由 `app.ts` 用 `app.route()` 挂载。环境绑定和上下文变量只在 `env.ts` 的 `AppBindings` 里声明，不用 `c.env as any` 绕过类型检查。
- **中间件**：用 `createMiddleware<AppBindings>()` 编写（`middleware/auth.ts` 的现有写法），负责鉴权、限流这类横切逻辑，不在路由里重复实现。
- **校验**：新路由用 `zod` 在入口处 `safeParse` 请求体和查询参数，失败时 `throw ApiError.badRequest(msg, { issues })`（§4.4）。暂不引入 `@hono/zod-validator`：它的错误响应格式和现有的 `ApiError` 不一致，要统一就得改 e2e 已经覆盖的行为。
- **路由保持薄**：路由处理函数只做校验 → 调用 `db/`、`lib/` 里的函数 → 组装响应。SQL 放在 `db/` 或路由文件底部的私有函数里，不内联在处理函数中间。
- **D1**：一律用 `prepare().bind()` 参数化，禁止拼接用户输入；需要原子性的多条写入用 `db.batch()`；并发写入用守卫条件（`WHERE rev = ?`）加上检查 `meta.changes`，也就是现有的 CAS 写法。
- **后台任务**：非关键路径的工作用 `c.executionCtx.waitUntil()`，并且要能容忍失败，比如 FTS drain、广播游标。
- **响应**：成功时 `c.json(body)`，失败时抛 `ApiError`。响应体的类型取自 `@shared/types`，不写内联对象字面量类型。

## 9. Rust

- **工具链**：edition 2024，版本由 `rust-toolchain.toml` 锁定。workspace 统一配置 lints（`desktop/src-tauri/Cargo.toml` 中已有），各 crate 用 `[lints] workspace = true` 继承。质量门是 `clippy --all-targets -D warnings` 加 `fmt --check`。
- **分层**：`note-core` 不依赖 tauri、网络和 UI；`note-sync`、`note-mcp` 依赖 `note-core`，不依赖 tauri；只有根包依赖 tauri。依赖方向由 Cargo 保证。
- **所有权与借用**：函数参数优先用借用（`&str`、`&[T]`、`&Path`），只有需要转移所有权时才传 `String`、`Vec`。避免无意义的 `.clone()`。热路径不做多余的分配。
- **类型驱动**：ID、rev、时间戳用 newtype（`NoteId(String)`、`Rev(i64)`），在构造时校验，避免混用。状态机用 `enum`，`match` 必须穷尽，不写 `_ =>` 兜底。
- **trait 作为接缝**：需要替换实现的边界定义成 trait，例如时钟 `Clock`、远端 HTTP 客户端 `RemoteApi`、事件发射 `EventSink`。生产代码注入真实实现，测试注入假实现（§2.1）。不为只有一个实现的内部模块定义 trait。
- **并发**：`note-core` 保持同步阻塞（与 AutoBee 的 route-core 一致），由调用方负责放进阻塞线程池。`note-sync`、`note-mcp` 用 `tokio`。跨 await 点不持有 `std::sync::Mutex` 的锁（clippy `await_holding_lock`）。
- **SQL**：只用 `rusqlite` 的参数绑定（`params![]`），禁止 `format!` 拼接 SQL 值。多条写入放在一个 `Transaction` 里。迁移只追加，不修改已发布的迁移（`db.rs` 已写明这一点）。
- **unsafe**：`unsafe_code = "deny"`。唯一例外是 DPAPI FFI，它放在 `shell::credentials` 里，每个 `unsafe` 块都要写 `// SAFETY:` 注释（`undocumented_unsafe_blocks = "deny"`）。
- **文档**：公开的项必须写 `///` 文档；返回 `Result` 的公开函数要写 `# Errors` 一节（`missing_errors_doc`）。

## 10. 测试规范

- 测试针对**行为和契约**：包括边界、不变量、状态转换、优先级和错误码。不测实现细节，不测转发或镜像式的回显，不测源码文本，不写"没有抛错"这种空断言。
- 分层：纯函数和状态类写单元测试（node 环境，注入假端口）；端口实现用契约测试，Web 端和桌面端跑同一组 `backend-contract` 用例（见 `10-详细设计-共享应用层.md`）；Web API 用 `e2e.mjs`；桌面打包产物用 `package:verify`（`smoke-native.mjs`）。
- 修 bug 时先写出能复现问题、此时失败的测试，修好后测试通过，并保留这个测试。
- 单元测试与组件测试确定、隔离、不访问外网；真实 API/IPC/打包冒烟必须运行真实实现，使用临时目录与本地测试实例，不写生产数据。截图和键盘交互属于界面验收，不能用状态替身测试替代。

## 13. 推送前本地 checklist（跨平台与发布）

顺序固定：本地低成本预检 → 本地实际行为验证 → 经批准推送 PR → GitHub 完整质量门与原生验收。本地按改动选择相关检查，不强制重复完整 `pnpm run ci`；保留该命令供需要时手动执行。不能把 GitHub Actions 当作逐个排查低级错误的调试环境，也不能用本地通过替代远端必需检查。

每轮复制下面清单到本地验收记录，填写实际命令、平台、结果和代码版本。状态只用“通过／失败／未验证／不适用（理由）”；未执行不能勾通过。改代码后，受影响项目的旧证据失效；Windows 通过不代表 Linux/macOS 通过。

### 13.1 低成本预检

- [ ] **范围与环境**：先核对改动涉及 AutoNote/Aether 哪些调用方、资产和脚本；检查本机 Windows、WSL Linux、macOS 是否可用，不到远端失败后才寻找本地环境。
- [ ] **命令与真实产物**：对改动的 `.mjs` 执行 `node --check <文件>`；实际调用 `node desktop/scripts/cargo.mjs check --workspace --all-targets` 验证 Windows cmd 引号/参数传递。Cargo 示例实际位于 `target/debug/examples/`，必须编译并运行真实产物，不能只拼路径。
- [ ] **图标**：逐一解析所有目标平台配置引用的图标路径；PNG 必须存在、正方形、8bit/channel RGBA（IHDR bit depth=8、color type=6），不能只检查扩展名；同时检查 Aether 三个窗口示例。转换格式时保持尺寸、逐像素比较内容不变，不等宏编译失败才检查。
- [ ] **版本与依赖**：版本号由发布 PR 维护，不手改；运行 `node desktop/scripts/version-check.mjs` 确认 `desktop/package.json` 与 Cargo workspace 一致、`tauri.conf.json` 不写版本；核对四处 Aether 引用为已通过 CI 的同一提交；更新锁文件后运行 `pnpm install --frozen-lockfile`。不使用忽略锁文件或安装失败的方式继续验证。
- [ ] **平台 API 与工具**：核对实际使用的原生 API、编译条件及工具依赖；例如 Swift 的 Foundation/CoreGraphics 桥接、Windows 专用 WebView 方法、Linux 的 readelf/identify/fusermount3。不能用 Windows 编译证明 Unix 分支正确。
- [ ] **包格式合同**：使用实际打包器行为制定检查。Tauri 会分别写入 APP/DEB 标记，不能要求不同包内二进制全 SHA 相等；各安装包独立校验 SHA256，另外核对版本、架构、build-id、各自格式标记及来源提交/run。运行现有 `pnpm --filter autonote-desktop test:release`。

### 13.2 实际行为与生命周期

- [ ] **Linux 文件语义**：涉及文件发布/备份时，先在本机 Linux/WSL 执行现有 transfer 回归；目录 fsync 使用可读目录句柄，覆盖替换、取消、发布失败、快照和重启读回。清理错误不能覆盖最初错误，也不能吞掉真实持久化失败。
- [ ] **凭据**：运行现有 `pnpm --filter autonote-desktop test:secrets`，真实服务中独立进程 seal/open/tamper/forget；Aether 改动还需其原生并发首次创建检查。macOS 临时 Keychain 配置与子进程必须处于相同用户偏好域，结束恢复默认钥匙串及搜索列表；Linux 使用隔离 D-Bus/Secret Service，禁止生产凭据、明文回落或放宽生产 ACL。
- [ ] **真实窗口**：运行打包产物，而不是预览替身；核对窗口归属 PID、数据根和库内容、实际绘制帧。等待可见完整帧，不能按 PNG 压缩字节数判断渲染成功，不能拿别的窗口代替。Web 改动需真实浏览器操作和截图。
- [ ] **退出与清理**：把“启动 → 操作 → 退出 → 子进程结束 → 挂载卸载 → 删除隔离目录”完整跑完才算冒烟通过。Linux portal 的 doc FUSE 挂载须在 D-Bus 结束前卸载；无清理残留、无后台进程、无用户生产数据改动。强杀仅限失败收尾，不能冒充正常退出。
- [ ] **本机平台限制**：缺少 macOS 或完整 Linux 桌面依赖时，明确列出未验证项目及原因；先完成所有可达验证，再申请一次远端原生验收，不把限制写成通过。

### 13.3 完整质量门与远端额度

- [ ] **完整远端质量门**：本地完成受影响模块的静态检查、相关测试与实际行为验证后提交/推送；GitHub 的提交规则、Web、三平台桌面与 AI 审查全部通过才允许合并。Web/共享静态检查集中执行一次，桌面各平台运行 `ci:desktop`，保留原生打包、凭据与冒烟。`pnpm run ci` 为可选本机入口，不是推送前置条件；Aether 改动仍遵守其仓库规则。
- [ ] **检查调用链**：执行前确认命令是否内嵌 verify/build，避免手动重复运行相同检查或重复打包；需要调整既有 CI 步骤时先取得用户同意，不能以节省额度为由削弱检查。
- [ ] **远端授权与额度**：推送前说明本地已通过项、未验证平台及会触发哪些 workflow/job；额度异常后停止自动触发，未经用户同意不增加预算、开通付费或反复重跑。本轮明确需要远端原生验证时，才推送/dispatch。
- [ ] **失败后先停再诊断**：先读取同一 run/commit 的首个实际错误，不只读外层 exit code；追踪共享根因及所有同类调用/资产，补齐本地复现和修复验证后再批量推送。不得每修一处就机械重跑三平台。
- [ ] **发布复用**：发布只使用同一提交/run 的绿色候选，复核五包集合、版本、架构、大小和哈希，不为上传重新编译、不混入本地包；完成匿名下载和哈希比对。账单阻断与代码失败分开记录，不谎称整个发行工作流全绿。
