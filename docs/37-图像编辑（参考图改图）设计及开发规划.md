# 37 图像编辑（参考图改图）设计及开发规划

> 范围：Aether（`aether-providers` 表/DTO、`aether-chat` 绘图工具与客户端、`tauri-plugin-aether` 运行接线、`packages/ui`）+ AutoNote Web（`web/src/worker`）。Web 与桌面同一套语义。
> 目标：接入支持改图的图像模型（`gpt-image-*`、`dall-e-2`、`qwen-image-edit`、`flux-kontext` 等 OpenAI 兼容 `/images/edits`）。每个配置都落库并被真实请求使用。

## 2. 我们怎么做

| Cherry | 我们 | 存储 | 运行时 |
| --- | --- | --- | --- |
| 图像编辑 Base URL | 请求配置弹窗新增该字段 | **新增列** `endpoints.image_edit_base_url TEXT`（桌面 v7，Web `ai_endpoints` v25） | `/images/edits` 地址 = `image_edit_base_url ?? base_url`（同 Cherry：留空用 API 地址） |
| 模型声明 `modes.edit` | 绘图（image 类型）模型的“支持参考图（改图）”开关 | **复用** `models.can_vision`：对 image 模型表示“接受输入图片” | 绘图模型 `canVision=true` 时工具才带 `image_ids` |
| `maxInputImages` | 固定上限 4（与对话附件上限一致） | 无 | 工具 schema `maxItems: 4` |
| `image_ids` | 同名参数，id 由本轮生成的“可用图片清单”给出 | 无（引用已有 `turn_images`/`ai_turn_images`） | 执行时按 id 取字节 |
| multipart `/images/edits` | 同 | — | 桌面手写 multipart 正文（不加 reqwest `multipart` 特性，避免新依赖）；Web 用原生 `FormData` |
| 蒙版 / 绘图页 | **不做** | — | 我们没有绘图页与涂抹界面，做了就是表面配置 |

### 2.1 可用图片清单

运行准备时收集当前历史路径上仍未过期的图片，**从新到旧最多 8 张**：本条消息的输入图片，然后历史各轮的生成图片与输入图片。按顺序编号 `image-1`…`image-8`，写进本轮 `generate_image` 的描述：

```
Images you can pass in image_ids (newest first):
image-1: attached by the user in this message
image-2: generated in an earlier reply
```

- 没有可用图片时不加 `image_ids` 参数（与模型不支持时相同）。
- 字节在工具执行时按 id 懒加载（不预读 8×4 MiB）。
- 本轮内刚生成的图片不在清单里（同一回复里“先生成再改”很少见；需要时下一轮引用）。
- 未知 id → `bad_request("image_ids","unknown")`；已过期 → `bad_request("image_ids","expired")`；模型不支持却传了 → `bad_request("image_ids","unsupported")`；超过 4 张 → `bad_request("image_ids","too_many")`。工具失败按现有方式把错误文本回填给对话模型。

## 3. 接口

```ts
type Endpoint     = { …现有, imageEditBaseUrl: string | null }
type EndpointSave = { …现有, imageEditBaseUrl?: string | null }   // 省略 = 保持
// generate_image 参数
{ prompt: string(1..4000), size?: "1024x1024"|"1024x1536"|"1536x1024", image_ids?: string[](1..4) }
```

- 校验同 `imageBaseUrl`（trim、空串→null、`http(s)://`、≤2048 字节，错误 `bad_request("imageEditBaseUrl","invalid_url")`）。
- `Connection` 加 `image_edit_base_url: Option<String>`（经 `api_base` 规范化）。
- 编辑请求：`POST {base}/images/edits`，multipart 字段 `model`、`prompt`、`size`、`n=1`，图片单张字段名 `image`、多张每张 `image[]`，文件名 `image-N.{png|jpg|webp|gif}`、带各自 MIME；自定义请求头、密钥轮换与 401/403/429 换钥同绘图；**不**设 `content-type`（由 multipart 边界决定）。返回解析与 `/images/generations` 共用（`b64_json` 或 `url`）。
- 生成结果照旧存为 `kind='generated'`，界面不变。

## 4. UI

- 请求配置弹窗：“图像生成 Base URL”下方加“图像编辑 Base URL”，提示“用于 /images/edits；留空时使用 API 地址”。
- 模型设置弹窗：`modelType === 'image'` 时显示开关“支持参考图（改图）”（绑定 `canVision`），说明“开启后，对话中可让模型基于已有图片修改”。

## 5. 执行

1. Aether 后端：表 v7 + DTO + 校验 + `Connection` → `aether-chat`：`generate_image_spec(choices)` 带清单、`edit_image` 客户端（手写 multipart）→ 插件：运行准备时收集清单（当前输入 + 历史路径）、执行时按 id 取字节 → `pnpm kit:dto`。测试：v6→v7；multipart 字段/文件数/文件名；单张 `image`、多张 `image[]`；编辑地址回退；未知/过期/不支持/超量；换钥与自定义头。
2. Aether UI：两处弹窗字段、i18n、测试。
3. Aether 文档：`docs/20` §2/§3/§5、`docs/11` 列。`pnpm run ci` → 推送。
4. AutoNote Web：schema v25、`providers.ts` 读写校验、`runs.ts` 收集清单与执行、`painting.ts` `editImage`（`FormData`）；测试同上；改 4 处 pin；`pnpm run ci`。
5. 验收（回环上游记录 multipart）：附一张图让模型“把背景改成蓝色”→ 上游收到 `/images/edits`（含 1 个文件、prompt、model、自定义头、密钥）；下一轮“再改成红色”引用上一轮生成图；关闭“支持参考图”后工具无 `image_ids`；清空编辑地址后回到 API 地址。
