# 23 详细设计：AI 模型服务

> 状态：阶段设计基线。A1 桌面一期按本文实施；A2 Web 二期只做设计，未开工。
> 来源：参考项目模型配置与编辑器 AI 动作的实际实现（服务商 → 线路 → 已选模型 → 角色绑定，DPAPI 加密密钥，按模型名推断类型）；本文按 AutoNote 的用途裁剪。契约优先级同 00 §1。

## 1. 结论与边界

- 目的：为 **AI 对话** 与 **AI 写作** 提供统一的模型配置、流式调用和编辑器动作。`chat` 与 `writing` 是产品角色，不是两个模型协议，也不是写死的模型名称。
- `chat` 用于笔记页右侧长对话；`writing` 用于编辑器内选区/光标动作。设置页分别绑定两个已保存的 `chat` 类型模型。
- 角色解析：对话请求默认解析 `chat`；写作请求固定解析 `writing`。`writing` 未绑定时只允许明确的兼容回落到 `chat`，UI 必须显示“正在使用对话模型回落”，不能假装写作模型已配置。
- 一期仅桌面。Web 二期复用同一产品合同：共享 UI、请求 DTO、结果预览和写回语义；桌面使用 Tauri + DPAPI，Web 使用 Worker + CredentialVault + 用户级限流。
- 协议三种：`anthropic-messages`、`openai-chat`、`openai-responses`。不做 Gemini 原生协议（经 OpenAI 兼容地址接入即可）。
- 模型类型与能力沿用参考项目的按名推断规则（§4），用户可逐个改类型，改过的标记为 `user` 不再被推断覆盖。
- 角色只保留 AutoNote 当前使用的两个：`chat`（对话）与 `writing`（正文改写/续写）。向量/重排/识图等用到时再加，不预留空角色。
- 不做：代理、自定义请求头、每线路超时、预置服务商、多模型同时写作、自动覆盖正文、用量计费。

## 2. 数据模型

### 2.1 SQLite（core 迁移 v5，只追加）

```sql
CREATE TABLE ai_providers (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, position INTEGER NOT NULL,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE TABLE ai_endpoints (
  id TEXT PRIMARY KEY, provider_id TEXT NOT NULL REFERENCES ai_providers(id) ON DELETE CASCADE,
  slug TEXT NOT NULL, base_url TEXT NOT NULL,
  protocol TEXT NOT NULL CHECK (protocol IN ('anthropic-messages','openai-chat','openai-responses')),
  key_ciphertext BLOB, position INTEGER NOT NULL,
  UNIQUE (provider_id, slug)
);
CREATE TABLE ai_models (
  endpoint_id TEXT NOT NULL REFERENCES ai_endpoints(id) ON DELETE CASCADE,
  model_id TEXT NOT NULL, model_type TEXT NOT NULL, type_source TEXT NOT NULL,
  context_window INTEGER, can_vision INTEGER NOT NULL DEFAULT 0, position INTEGER NOT NULL,
  PRIMARY KEY (endpoint_id, model_id)
);
CREATE TABLE ai_roles (
  role TEXT PRIMARY KEY CHECK (role IN ('chat','writing')),
  endpoint_id TEXT NOT NULL, model_id TEXT NOT NULL,
  FOREIGN KEY (endpoint_id, model_id) REFERENCES ai_models(endpoint_id, model_id) ON DELETE CASCADE
);
```

- 级联删除保证删服务商/线路/模型时角色绑定一并失效，不留悬空引用。
- 密钥只存 DPAPI 密文（`SecretStore`，与同步 cookie 同一实现）；无明文回退，加密失败即保存失败。非 Windows 一期不支持保存密钥（与同步一致）。

### 2.2 DTO（camelCase，请求 `deny_unknown_fields`）

```ts
type AiProtocol = 'anthropic-messages' | 'openai-chat' | 'openai-responses'
type AiModelType = 'chat' | 'image' | 'video' | 'tts' | 'stt' | 'embedding' | 'rerank' | 'unknown'
type AiTypeSource = 'inferred' | 'user'
type AiRole = 'chat' | 'writing'

interface AiModel { id: string; modelType: AiModelType; typeSource: AiTypeSource; contextWindow: number | null; canVision: boolean }
interface AiEndpoint { id: string; slug: string; baseUrl: string; protocol: AiProtocol; keyMasked: string | null; probeUrl: string; models: AiModel[] }
interface AiProvider { id: string; name: string; endpoints: AiEndpoint[] }

interface AiEndpointSave { id?: string; slug: string; baseUrl: string; protocol: AiProtocol; apiKey?: string; models: AiModel[] }
interface AiProviderSave { id?: string; name: string; endpoints: AiEndpointSave[] }

interface AiProbeResult { probeUrl: string; models: (AiModel & { group: string | null })[]; error: AiProbeError | null }
interface AiProbeError { kind: 'missing_key' | 'unauthorized' | 'not_found' | 'rate_limited' | 'status' | 'timeout' | 'connect' | 'invalid_body'; status: number | null; message: string | null }

interface AiModelRef { endpointId: string; modelId: string }
interface AiRoleBinding { role: AiRole; binding: (AiModelRef & { label: string }) | null; isFallback: boolean }

interface AiWriteRequest {
  action: 'polish' | 'rewrite' | 'shorten' | 'expand' | 'continue'
  text: string
  context?: string
  language?: string
  noteTitle?: string
}

type AiWriteEvent =
  | { kind: 'delta'; text: string }
  | { kind: 'done'; inputTokens: number | null; outputTokens: number | null }

interface AiWriteResult {
  text: string
  model: AiModelRef
}

interface AiChatMessage { role: 'system' | 'user' | 'assistant'; content: string }
type AiChatEvent =
  | { kind: 'delta'; text: string }
  | { kind: 'done'; inputTokens: number | null; outputTokens: number | null }

// AiChatEvent and AiWriteEvent are intentionally wire-compatible; the product
// layer gives writing a separate action/result contract and a separate role.
```

## 3. 桌面 IPC 命令

| 命令 | 参数 | 结果 | 说明 |
| --- | --- | --- | --- |
| `ai_providers_list` | — | `AiProvider[]` | 按 position 排序 |
| `ai_provider_save` | `{ provider: AiProviderSave }` | `AiProvider[]` | 单事务：新建/更新服务商；未出现在请求里的线路删除；模型整表替换；返回完整列表 |
| `ai_provider_delete` | `{ id }` | `{ ok: true }` | 级联删除线路、模型、绑定 |
| `ai_endpoint_key_reveal` | `{ id }` | `{ key: string }` | 仅此命令返回明文；日志只记 id |
| `ai_endpoint_probe` | `{ id }` | `AiProbeResult` | 读已保存的地址与密钥；网络失败放进 `error`，不抛错 |
| `ai_roles_get` | — | `AiRoleBinding[]` | `writing` 未绑时回落 `chat` 并标 `isFallback` |
| `ai_roles_set` | `{ role, binding: AiModelRef \| null }` | `AiRoleBinding[]` | 绑定必须指向已保存模型且类型为 `chat` |
| `ai_chat` | `{ jobId, request: AiChatRequest }` + `onEvent: Channel<AiChatEvent>`（见 §7.1） | `{ ok: true, conversationId }` | 默认解析 `chat`；`jobs_cancel(jobId)` 取消 |
| `ai_write` | `{ jobId, request: AiWriteRequest }` + `onEvent: Channel<AiWriteEvent>` | `{ ok: true, model: AiModelRef }` | 固定解析 `writing`；不创建对话历史；`jobs_cancel(jobId)` 取消 |

`ai_write` 的成功结果只返回模型引用和流式文本事件；前端在用户点击“替换/插入”前不得写入笔记。未配置 `writing` 时，结果必须带 `isFallback=true` 的解析信息，界面显示“使用对话模型回落”；若产品策略关闭回落，则返回 `bad_request(details.field='ai.role')`。
- 写操作走 core 的 `Library`，事务内只做本地 SQL；网络请求一律在 `note-ai` 里、事务外进行。`ai_write` 不写 `ai_conversations`/`ai_messages`，仅返回流式结果，用户确认后由笔记写入队列保存。
- 加解密在命令层：保存时用 `DpapiSecretStore` 把明文变成密文再交给 core；core 只存取密文，不依赖 `SecretStore`。`ai_chat`/`ai_write`/探测/显示密钥时读密文、解密、用完即释放（`Zeroizing`），不缓存明文。

## 4. 推断规则（沿用参考项目）

按模型 id 小写后匹配，先类型后能力：

| 规则 | 结果 |
| --- | --- |
| 含 `rerank` | rerank |
| 含 `embed` / 以 `bge-`、`voyage-` 开头 | embedding |
| 含 `whisper` / `transcri` | stt |
| 含 `tts` | tts |
| 含 `veo` / `sora` / `video` | video |
| 含 `dall-e` / `image` / `imagen` | image |
| 以 `claude` / `gpt` / `o` + 数字 / `gemini` / `deepseek` / `qwen` / `glm` / `kimi` / `moonshot` 开头 | chat |
| 其余 | unknown |

上下文与识图：`claude*` 200k（`anthropic-messages` 下可识图）；`gpt*`、`o\d*` 400k 且可识图；`gemini*` 1M 且可识图；其余 chat 默认 128k，非 chat 为 null。分组按前缀（claude/gpt/gemini/...，其余 `other`）只用于探测结果展示，不入库。

## 5. 网络

- 地址规范：去掉末尾 `/`；若路径不以 `/v1` 结尾则补 `/v1`（用户已写 `/v1` 不重复）。
- 探测：`GET {base}/models`，`Authorization: Bearer <key>`（三种协议都按 Bearer，兼容中转站）；Anthropic 官方地址额外带 `x-api-key` 与 `anthropic-version: 2023-06-01`。超时 20 秒，响应体上限 4 MiB；解析 `data[].id`、`models[].id` 或字符串数组；0 个模型算 `invalid_body`。
- 对话：
  - `anthropic-messages`：`POST {base}/messages`，头 `x-api-key`、`anthropic-version: 2023-06-01`；system 消息并入 `system` 字段；`max_tokens` 缺省 4096；SSE `content_block_delta.delta.text`，用量取 `message_start.usage.input_tokens` 与 `message_delta.usage.output_tokens`。
  - `openai-chat`：`POST {base}/chat/completions`，Bearer，`stream: true`、`stream_options.include_usage: true`；增量取 `choices[0].delta.content`，用量取末块 `usage`。
  - `openai-responses`：`POST {base}/responses`，Bearer，`stream: true`，system 并入 `instructions`；增量取 `response.output_text.delta` 的 `delta`，用量取 `response.completed.response.usage`。
  - 统一：连接超时 15 秒、首字节前总超时 60 秒、流中 60 秒无数据视为超时；HTTP 非 2xx 映射为 `unauthenticated`(401/403)、`not_found`(404)、`too_many_attempts`(429)、其余 `internal`/`offline`；每个块检查取消标志。

## 6. 共享界面

- 设置新增“模型服务”分区（宿主扩展，后端带 `ai` 端口时显示）。服务商配置区沿用 voynote 的双栏信息架构：左侧服务商 rail，右侧线路折叠卡；线路字段使用项目现有 Field/Input/Select/Button 组件和语义 token，不能自造第二套表单样式。
- 角色区保留两行：
  - **对话模型**：用于笔记页右侧 AI 对话。对话 UI 默认使用此绑定，不要求用户每次重新选模型；可选模型只作为明确的临时覆盖。
  - **写作模型**：用于编辑器内“润色/改写/缩短/扩写/继续写作”。编辑器动作默认使用此绑定；未单独绑定时显示“使用对话模型回落”，不能显示为已配置写作模型。
- 角色选择器显示真实模型名和服务商，不显示空的“角色（—）”。角色变化后，已打开的对话/写作面板重新读取 roles/providers。
- 一期只放在桌面宿主扩展（`desktop/src/lib/settings/`）；二期 Web 复用相同信息架构、字段语义和角色合同，不复制一套不同的模型配置 UX。

## 6.1 笔记页 AI 写作助手

写作不是第二个长对话框，而是编辑器的短动作。

- **触发**：选中文字后显示编辑器浮动工具条；无选区但光标在正文中时，工具条提供“继续写作/生成下一段”。桌面可从编辑器右键/快捷键打开；Web 使用相同按钮和动作，不依赖 Tauri 菜单。
- **一期动作**：`polish` 润色、`rewrite` 改写、`shorten` 缩短、`expand` 扩写、`continue` 继续写作。第一版不做翻译、附件、多模型并排、RAG 和自动整篇改写。
- **上下文**：有选区时 `text` 是选区原文，`context` 是选区前后有限窗口；无选区时 `text` 为空，`context` 是光标前后有限窗口。正文窗口由前端裁剪，单次请求总字符上限 24k；不发送整篇笔记，除非产品后续明确增加“总结全文”。
- **预览而不是覆盖**：流式输出进入“AI 建议”预览区；默认不改变编辑器。用户显式点击“替换原文”“插入到光标”或“复制”后才产生副作用；取消/关闭/失败不修改正文。
- **写回**：替换使用请求开始时保存的 selection 范围，并在编辑器文档版本变化时拒绝静默覆盖，改为显示“原文已变化，请重新选择”；插入使用当前光标。写回复用现有 notes 编辑队列，不能绕过 `NotesState.editContent`/编辑器变更事件。
- **模型**：前端不传具体模型作为默认值；后端固定解析 `AiRole::Writing`。临时切换模型是显式的“换模型”操作，不改变设置中的写作绑定。
- **状态**：`idle → generating → preview → applying/applied`；Esc/停止为 `cancelled`；上游错误显示清洗后的原因；生成中的按钮禁用重复提交。
- **无写作模型**：若允许回落，预览头显示“使用对话模型回落”；若不允许，显示“未配置写作模型 → 去设置”。默认产品选择：允许回落但必须显式标记，以保证首次使用可用。

## 6.2 桌面与 Web 宿主差异

| 能力 | 桌面 | Web |
| --- | --- | --- |
| 模型配置 | Tauri IPC；API key 用 DPAPI 密文 | Worker HTTP；按用户隔离，密钥进入 CredentialVault，不进 D1 明文 |
| 对话流 | Tauri Channel | Worker SSE/ReadableStream，前端 AbortController 取消 |
| 写作流 | Tauri Channel；`jobs_cancel` | `/api/ai/write` SSE；请求级限流与取消 |
| 编辑器写回 | CodeMirror selection + NotesState 写队列 | Web 编辑器 selection + 同一 NotesState 写队列 |
| 权限 | 本地用户 | 登录用户；owner/站点策略决定是否开放 AI |
| SSRF | 桌面用户自行负责地址 | 默认阻止回环/私网地址；owner 显式放开才允许 |
| 错误 | 结构化 AppError | 结构化 HTTP 错误，不能透出 Worker/上游敏感诊断 |

## 7. 前端端口（为桌面与 Web 共享合同）

```ts
interface AiPort {

  revealKey(endpointId: string, options?): Promise<string>
  probe(endpointId: string, options?): Promise<AiProbeResult>

  listConversations(options?): Promise<AiConversationSummary[]>
  getConversation(id: string, options?): Promise<AiConversation>
  deleteConversation(id: string, options?): Promise<{ ok: true }>
  chat(request: AiChatRequest, onEvent: (event: AiChatEvent) => void, options?): Promise<{ conversationId: string }>
```

桌面一期类型先放 `desktop/src/lib/ipc/ports/ai.ts`，后续迁移到 `@app/backend`；桌面和 Web 的 `AiPort` 行为必须一致，只有 transport、凭据、安全策略不同。

## 7.1 笔记页 AI 对话（A1-5）

对照 voynote：对话放在笔记主页面右侧，不放设置里；照搬其最小核心，去掉多模型分叉、附件、RAG、翻译、分支等。也补上它的两个缺口：重启后能回到历史对话；笔记正文不在每轮重复。

- **位置**：工作区右侧停靠栏（宽 360px，`border-l`），与笔记并排可同时编辑。由笔记头部的 ✨ 按钮、命令面板“AI 对话”和 `mod+shift+l` 开关；开关状态随布局偏好保存。窄屏（<768px）改为覆盖全屏，Esc 关闭。共享层只提供 `HostExtensions.workspacePanel` 槽位；桌面和 Web 在 `capabilities.ai` 开启时注入同一 ChatPanel 或等价共享组件。
- **对话与笔记的关系**：对话不绑笔记，删笔记不删对话。发送时若开着笔记，输入框上方显示“当前笔记：标题”标签（可点 × 本条不带）；带上时把当前编辑器正文（含未保存）截断到 24k 字符，放进本轮 system 提示，不写进消息记录。
- **模型**：默认解析设置中的 `chat` 角色，显示真实模型名；用户不需要每次重新选择模型。模型选择器只作为显式临时覆盖，默认项标记“默认”，设置页角色变化后打开的面板重新加载绑定。
- **存储**：迁移 v6 的 `ai_conversations`/`ai_messages`，对话独立于笔记；标题取首条用户消息前 40 字。
- **命令**：`ai_conversations_list`、`ai_conversation_get`、`ai_conversation_delete`；`ai_chat` 增加 `conversationId?`、`note?`，后端事务写用户消息，事务外流式，结束写 `done`/`failed`/`interrupted` 助手消息。历史只取 `done` 消息，按模型上下文窗口丢弃最早消息，最后一条用户消息必留。
- **界面**：历史下拉、新对话、关闭；助手 Markdown 使用现有安全 renderer；复制、插入到笔记光标处、最后一条重新生成；失败显示原因和重试；未配置 `chat` 时引导设置。对话不显示“写作模型”选择器。

## 7.2 笔记页 AI 写作（A1-6）

- **触发**：编辑器选中文字后显示 AI 写作浮动工具条；无选区时提供“继续写作/生成下一段”。桌面和 Web 使用同一动作列表，不依赖宿主菜单。
- **动作**：`polish`、`rewrite`、`shorten`、`expand`、`continue`。动作文案由 i18n 提供；首版不做翻译、附件、多模型并排、RAG、自动整篇改写。
- **请求**：`AiWriteRequest` 的 `text` 为选区，`context` 为选区前后有限窗口，`language` 为当前语言，`noteTitle` 可选；前端裁剪总长度到 24k 字符，不发送整篇笔记。
- **流式预览**：写作结果在编辑器旁的“AI 建议”预览区流式显示；默认不改变正文。操作按钮为“替换原文”“插入到光标”“复制”“取消”。
- **写回保护**：替换保存请求开始时的 selection 和文档版本；文档版本变化时拒绝静默覆盖，显示“原文已变化，请重新选择”。插入使用当前光标。写回统一走现有 NotesState/编辑器写队列。
- **模型**：前端不传默认具体模型；后端固定解析 `writing` 角色。写作绑定未配置时允许明确回落 `chat`，预览区必须显示“使用对话模型回落”；若用户关闭回落则返回 `bad_request` 并引导设置。
- **状态**：`idle → generating → preview → applying/applied`；停止为 `cancelled`；重复提交禁用；错误显示清洗后的上游原因。写作结果不写入聊天历史。
- **共享宿主**：桌面用 Tauri Channel + `jobs_cancel`；Web 用 Worker SSE + AbortController。动作、DTO、预览与写回合同一致，只有凭据、权限、限流、transport 不同。

## 8. A2 Web 二期设计（未实施）

- **共享产品层**：Web 复用 §6.1 的服务商/线路/角色 UI 语义与 §7.1/§7.2 的 ChatPanel、写作工具条、预览区；不另设计一套 Web 专用模型选择器。共享 `AiPort` 位于 `@app/backend`，桌面 IPC 和 Web HTTP/SSE 各自实现。
- **存储**：D1 新表 `ai_providers / ai_endpoints / ai_models / ai_roles`，每行带 `user_id`，主键改为 `(user_id, id)`；密钥不进 D1，加密后存现有 CredentialVault Durable Object，作用域 `ai-endpoint:<endpointId>`。
- **路由**：`/api/ai/providers`（GET/PUT/DELETE）、`/api/ai/endpoints/:id/key`（POST 显示，需二次输入当前密码或近期登录）、`/api/ai/endpoints/:id/probe`、`/api/ai/roles`、`/api/ai/chat`（SSE）、`/api/ai/write`（SSE）。全部要求登录与 `X-AutoNote-Client`。
- **写作请求**：Worker 接收 `AiWriteRequest`，服务端从用户的 `writing` role 解析 endpoint/model，不接受客户端任意覆盖默认模型；显式临时模型覆盖需要单独权限/参数校验。
- **安全**：默认禁止私网与回环 base URL 防 SSRF，owner 可在站点设置显式放开；对话和写作按用户限流、并发限制；日志与错误不含密钥、请求体、模型输出；显示明文需重新验证身份；列表只返回打码值。
- **流式与取消**：Worker 用 `fetch` + `ReadableStream` 解析 SSE；前端用 AbortController；断线结果标记 `cancelled`/`failed`，不能自动重复产生写回副作用。
- **共享推断**：模型分类/能力推断抽到 `packages/shared`，桌面 Rust 与 Worker 使用同一 fixture/契约测试，避免两端对同一模型给出不同类型。
- **能力门控**：`capabilities.ai` 为 true 时显示 AI 入口；Web 非 owner 或站点关闭时不显示服务配置、对话和写作按钮，已有历史不泄露。
