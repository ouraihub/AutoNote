## 1. 一句话

以 AutoNote v0.8.0（React 19 + Hono + Cloudflare）为蓝本，重写出两个产品，放在同一个 monorepo `ouraihub/AutoNote` 里，前端统一使用 Svelte 5：

| 产品 | 目录 | 形态 | 数据 |
| --- | --- | --- | --- |
| AutoNote Web | `web/` | Cloudflare Workers：Svelte 5 SPA 加上移植过来的 Hono Worker | D1 + R2/KV + DO，与 AutoNote 兼容 |
| AutoNote Desktop | `desktop/` | Tauri 2 + Svelte 5 + Rust workspace，参考 AutoBee | 本地 SQLite，可选同步到某个 Web 实例 |
| 共享代码 | `packages/shared/` | 纯 TS：类型、常量、中英文语言包、Markdown 工具 | 无 |

CI 按路径拆分：
- `.github/workflows/web.yml` 在 `web/**` 或 `packages/**` 有改动时触发，依次跑检查和 e2e。部署暂时改成手动：在 Actions → Web → Run workflow 里勾选 `deploy`，而且只能在 `main` 上执行。等项目完成后，再改回推送就部署。
- `desktop.yml` 在 Windows 上跑 `verify`。
- `desktop-release.yml` 在打 `desktop-v*` tag 时构建安装包，并发布到 GitHub Release。

MSVC 工具链由 `desktop/scripts/msvc-env.bat` 统一决定：
- 本地固定使用便携 MSVC（`PORTABLE_MSVC_ROOT`，默认 `D:\Applications\msvc-portable\msvc`）。即使机器上装了 VS Build Tools，或者当前是在 Developer Prompt 里，也不会用它们。如果 PATH 上排在最前的 `cl.exe` 不在便携目录下，脚本直接报错退出。
- 只有在 GitHub Actions 里（设置了 `CI` 环境变量），才使用 `ilammy/msvc-dev-cmd` 启用的 runner 自带 Build Tools。

## 2. 已确认的决策

| 编号 | 决策 | 来源 |
| --- | --- | --- |
| D1 | 使用一个 monorepo（`ouraihub/AutoNote`），CI 按路径拆分，两个产品独立发版：Web 目前手动部署，等项目完成后改回推送 `main` 就部署；桌面按 `desktop-v*` tag 发布。最初定的是拆成两个仓库，用户后来同意改为 monorepo | 用户确认 |
| D2 | Web 版后端移植现有的 Hono Worker：API 契约、D1 schema、备份格式都保持不变 | 用户确认 |
| D3 | 桌面版以本地 SQLite 为主存储，可选同步到 Cloudflare 实例 | 用户确认 |
| D4 | 桌面版提供 MCP 服务端 | 用户追加 |
| D5 | 桌面版不做公开分享、WebDAV/S3 备份、语义搜索和 CLI | 用户未勾选 |
| D6 | 两个产品的前端都用 Svelte 5 runes + Tailwind 4 + shadcn-svelte。Web 版是纯 Svelte + Vite（原因见 02 §3），桌面版是 SvelteKit adapter-static | 需求，加上 AutoBee 先例 |
| D7 | 产品名为 AutoNote，Logo 使用 `autonote.png`。用户可见文案都改名，协议标识（cookie 名、`X-AutoNote-*` 请求头、备份格式标识、IndexedDB 库名）保持不变，保证能连上已有的 AutoNote 实例 | 用户确认 |
| D8 | 桌面版的数据目录固定在 exe 同级的 `data\`，不使用 `%APPDATA%` | 用户确认：系统盘数据容易丢失 |
| D9 | 包管理器统一用 pnpm 12.5.1 | 骨架按此搭建，与 AutoBee 一致 |

## 3. 提议的决策（评审时确认）

| 编号 | 提议 | 理由 | 替代方案 |
| --- | --- | --- | --- |
| P1 | 桌面版同步复用 Web 版现有的 `/api/sync` 和 `/api/notes` 协议，服务端不做改动 | 协议里已经有 cursor 增量、`rev` CAS 和 409 冲突返回，见 01 §3 | 新开一套同步 API：两边都要改，还要多维护一份契约 |
| P2 | 桌面版 MCP 采用本地 Streamable HTTP（监听 `127.0.0.1`，需要 Bearer Token），工具集与 Web 版 MCP 同名同参 | 同一个 AI 客户端配置两边都能用；只要应用在运行就能提供服务 | 用 stdio 子进程：必须另写一个 bin，并处理 SQLite 多进程写锁 |
| P3 | ~~复制两份 `shared/`~~：已被 D1 取代，改为单一的 `packages/shared`，通过 pnpm workspace 引用 | — | — |
| P5 | 许可证沿用 LGPL-3.0-only，并保留 AutoNote 的版权声明 | 这是衍生作品，LGPL 要求保留原许可 | 改用其他许可证：需要先取得原作者授权 |

## 4. 范围之外

- 修改 AutoNote 仓库本身
- 移动端原生 App（Web 版保留移动端布局和 PWA）
- 桌面版里的分享、远程备份、语义搜索、CLI（见 D5）
- 桌面版多账号：一个本地库只对应一个用户，同步时绑定一个远端账号

## 5. 最大的风险

1. 工作量：AutoNote 客户端约 2.9 万行，其中 `store/notes.ts` 一个文件就有 2875 行，乐观更新、outbox 和冲突恢复都在这个文件里。桌面版还要在 Rust 里重写一份等价的写入语义。详见 01 §4。
2. 同步语义漂移：桌面版的 SQLite 和 Web 版的 D1 必须遵守同一套 `rev` / `content_hash` / `changes` 规则，否则会出现"两边都显示已保存，内容却不一样"。对策是用同一组契约用例同时跑两端，见 04 的 M-SYNC 阶段。
3. 中文全文检索：D1 通过 `segmentCJK` 预分词后写入 FTS5 `unicode61`。桌面版必须用同一个分词算法（Rust 版本），否则两端搜索结果会不一致。
