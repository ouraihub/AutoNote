## 1. 包结构、工具与归属

`packages/app` 是 private 源码包，不单独发布或产出另一份 JS。宿主 Vite 编译 Svelte 源码。生产代码不 import 宿主；宿主不深入访问 app 的私有模块。

| 路径（相对 packages/app/src） | 公开入口与责任 |
| --- | --- |
| `backend/{port,errors,change-feed}.ts` | `@app/backend`：Backend、BackendError、ChangeFeed |
| `platform/{clock,prefs,notifier}.ts`、`log/logger.ts` | 可替换的运行时边界；不为纯函数造服务 |
| `i18n/{runtime.svelte,errors}.ts` | `@app/i18n`：语言状态、t、错误文案 |
| `theme/{tokens.css,apply,bootstrap}.ts` | 主题/首屏配置，CSS 文件后缀按实际内容使用 |
| `styles/{app,editor,prose,inter}.css` | 原 参考项目 token 与排版迁移，避免两份主题 |
| `components/ui/` | 基础表单、覆盖层、反馈；bits-ui 行为封装 |
| `markdown/{renderer,enhance,embeds,prism,data-attr}.ts` | 渲染、净化、懒加载、嵌入 |
| `editor/{CodeEditor.svelte,commands,completion,paste,decorations,live-preview}.ts` | `.svelte` 与 `.ts` 按文件用途分别建，组件持有 EditorView |
| `state/{notes,ui,session,settings}.svelte.ts` | 每次挂载独立状态，不用全局单例 |
| `state/{merge,mutations,selectors}.ts` | 纯算法，可由 Web 缓存层复用 |
| `features/{shell,sidebar,list,workspace,preview,command,settings,share,graph,auth}/` | 每个 feature 一个容器，其余只依赖 props |
| `root/{AppRoot.svelte,context,types,index}.ts` | `@app/root`：AppDeps、mountApp、AppHandle |
| `gallery/Gallery.svelte` | 开发模式的 `/__gallery`；不是生产首页 |
| `backend/contract/` | 无 vitest 依赖的行为场景；单独 runner 绑定 vitest/真实宿主 |

别名 `@app`、`@shared` 在 app 检查配置和两个宿主统一指向源码目录；SvelteKit 通过 kit.alias 生成类型路径，不手改 `.svelte-kit`。`symlink:false` 的当前工程不能依赖工作区自动链接来解决别名。根 lockfile 由集成负责人维护，并行任务不能同时 install。

### 1.1 工具版本策略

Svelte 5.57.1、Vite 8.3.0 沿用骨架。共同契约测试使用同一 Vitest 4.1.10 与 TypeScript 5.9.3 基线：S0-1 将 desktop 的对应工具版本收敛，并用两端检查验证，不顺手升级 runtime。若现有 Kit 明确不支持此 TS 版本，以完整兼容验证后的统一版本替换，必须同时更新两个宿主和本文，不能让一个契约模块被两个 vitest 实例加载。

业务依赖放实际使用包：CodeMirror 6、markdown-it 及现有插件、DOMPurify、Prism、KaTeX、Mermaid、DiceBear、Inter 字体归 app；idb-keyval 归 web；Tauri API 归 desktop。bits-ui 与 `@lucide/svelte` 为 Svelte 基础件。只引入当前任务实际调用的包；锁定成功安装的精确版本，不把未验证的候选版本写成事实。

S0-2 建根 eslint 配置，分区约束新 app/Web宿主/桌面宿主，既有 worker 不全量整改；检查越层 import、未处理 Promise、硬编码颜色与可见文案。formatter 只作用任务修改文件，不重排整个移植仓库。S0-3 配 node 与 jsdom 两组 vitest：纯转换/node，DOM组件/jsdom；`.svelte.ts` 经 Svelte 插件编译。

## 2. Backend 完整端口合同

### 2.1 类型与生命周期

复用 `@shared/types` 的实体、请求和响应，不修改 Worker 线上结构。新增持久/跨端 DTO 放 `packages/shared/src/backend-types.ts`，端口、File、AbortSignal 等运行时类型留在 `backend/port.ts`。

```ts
type ErrorCode = ApiErrorCode | 'offline' | 'cancelled' | 'request_timeout' | 'invalid_response'
interface CallOptions { signal?: AbortSignal }
interface NoteWriteOptions extends CallOptions { writeId: string }
type NoteWriteResult =
  | { queued: false; writeId: string; note: Note }
  | { queued: true; writeId: string; noteId: string; rev: number }
type WriteQueueEvent =
  | { kind: 'pending'; count: number }
  | { kind: 'settled'; writeId: string; noteId: string; note: Note }
  | { kind: 'recovered'; writeId: string; noteId: string; copy: Note; reason: 'deleted' }
  | { kind: 'failed'; writeId: string; noteId: string; code: ErrorCode; retained: boolean }
interface BackendSession extends Omit<SessionInfo, 'site'> {
  site: Omit<SiteInfo, 'attachmentStorage'> & { attachmentStorage: SiteInfo['attachmentStorage'] | 'local' }
}
interface FlushResult { pending: number; failed: number }
interface TagPatchResult { tag: Tag | null; renamed: number }
interface AttachmentPage { files: AttachmentWithUsage[]; nextCursor: string | null }
interface ProgressEvent {
  jobId: string; phase: 'validating' | 'reading' | 'writing' | 'uploading' | 'finalizing'
  completed: number; total: number | null; terminal: boolean
}
```

`Backend` 的端口集合与 capabilities 见 02 §3，并增加 `dispose(): Promise<void>`。ChangeFeed 只有一条：02 §6 的 `sync/library/write/settings/connectivity`。不再定义第二个 `watchWrites` 通知源。writeId 由 app 的 NotesState 生成并传给正文 patch，随后输入用新 ID，防止旧成功确认清掉新脏写。

`BackendError(code,status,message,details?)` 保留结构化错误。取消转 `cancelled`，超时转 `request_timeout`，HTTP 2xx 但非法 JSON 转 `invalid_response`；不要全部当 offline 以免错误入队。用户取消不弹危险 toast。`details` 只保留已知安全字段（server、deletionCursor、retryAfter、字段路径），不透传内部 SQL/磁盘路径。

## 3. 平台接缝与装配

`AppDeps={backend,clock,logger,prefs,notifier,extensions}`。`mountApp(target:HTMLElement,deps:AppDeps):AppHandle`；`AppHandle={flush():Promise<FlushResult>;openNote(id:string|null,pane?:'primary'|'secondary'):Promise<void>;destroy():Promise<void>}`。openNote等待认证、布局恢复和笔记快照就绪，新的导航取代尚未执行的旧导航；销毁取消待执行导航。flush先提交各视图缓冲，再持久化笔记、设置和布局。destroy先flush本地再取消监听/销毁EditorView；失败由宿主决定是否退出，不吞错。Web已持久pending不阻止销毁且不删outbox；桌面pending或任一宿主failed均阻止。

- Clock：`now():number`；可注入计时器仅用于需要确定性调度的模块，不给每个函数造Clock。
- Logger：debug/info/warn/error(event,fields?)；生产宿主输出，app不自己持久日志。
- PrefsStore：`load(key):unknown`、`save(key,value):void`、`remove(key):void`；只存布局/最近笔记等非正文数据。会话与笔记日志不混进PrefsStore。
- Notifier：`toast({id?,key,params?,tone,action?})`、`confirm({titleKey,bodyKey,params?,danger?}):Promise<boolean>`；确认标题与正文共用插值参数，UI反馈实现由AppRoot装配，禁止弹浏览器alert。
- HostExtensions：`settingsSections: HostSettingsSection[]`、`aboutPanels: HostPanel[]`、`onNoteOpened?(id)`、`subscribeIntents?(listener):unsubscribe`；Section的组件通过Svelte Component类型表达，包含id/order/titleKey/canShow。HostPanel可携带`props?:Readonly<Record<string,unknown>>`，About按order渲染并传入组件；宿主状态显式注入而非全局单例。注入宿主特性不让共享组件import宿主。

## 4. i18n

迁移 参考项目 `lib/i18n.ts` 的加载、插值、错误映射，替换useLocale。`I18nState` 字段 locale/messages/loaded；`init(locale)`、`setLocale(locale)`、`t(key:MessageKey,params?)`。t在模板执行时必须读取响应式locale，不能只靠一个非响应函数捕获旧词典。默认locale取持久偏好再取系统，支持zh-CN/en-US；回退英文，但缺键在开发检查时失败。异步切换A→B→A用generation防旧加载覆盖。日期数字格式器由当前locale构造缓存，语言变化清缓存。API错误按code翻译，禁止靠翻译文本做分支。

## 5. 主题与首屏

唯一默认值取 `DEFAULT_SETTINGS.appearance`，当前accent=cinnabar，不继承旧ui.ts的indigo分叉。宿主在首屏启动脚本读取同一份安全布局偏好，设置 `data-theme/accent/background`；构建从theme/bootstrap.ts生成脚本内容，禁止两份手写默认值。theme/system监听matchMedia并清理，用户明确设置优先；尊重prefers-reduced-motion。CSS token与参考项目保持语义对应，组件不得硬编码调色板。桌面窗口/WebView背景与首屏一致，截图覆盖浅色、深色和7色。

## 7. Markdown 管线

保留 `renderMarkdown(source,options)`、`renderMarkdownBlocks`、parseWikiTarget/parseFenceInfo、KaTeX/Mermaid/Prism按需加载。顺序：解析源文→生成HTML→DOMPurify净化→挂载→异步增强。任何异步结果先校验render generation；切换笔记后不能插入旧图表。

依赖注入 `RenderServices={resolveNote(target,signal),resolveAssetUrl,openNote,toggleTask}`。embeds/live-preview不访问NotesState单例；递归嵌入有visited与深度上限，未知目标显示可点击缺失状态，不无限抓取。HTML输出和SVG/URL不能绕过净化；禁止javascript:、本地file:以及未授权协议。任务勾选通过源行号修改正文，不直接把DOM序列化回Markdown。预览交互态（tabs/折叠）按笔记ID与块标识保存，切换新笔记不得沿用错误状态。

## 8. CodeMirror

`CodeEditor` props：noteId/value/title/settings/services/onChange/onHeadings/onViewReady。onMount创建一次EditorView，Compartment重配行号/主题/拼写/预览，不因每次输入销毁重建。外部正文仅在其与当前doc确实不同且来源非本次回声时dispatch；避免撤销栈被自动保存刷新清空。双窗格每窗格独立EditorView和选择区。

commands/decorations/completion/paste按原文件迁移。粘贴HTML必须净化和转换，附件上传经files端口；上传完成时校验noteId与generation，不把结果插入已切走笔记。IME composition期间不强行改选区；异步补全取消旧查询。专注/打字机模式只修改视图行为，不改正文。

## 9. 状态类与算法

| 类/函数 | 字段与公开方法 | 不变量 |
| --- | --- | --- |
| `NotesState` | summaries/contents/loadErrors/dirtyById/saveState/cursor；bootstrap/open/editTitle/editContent/flush/create/patch/remove/restore/purge/duplicate/applySync | 每笔记独立writeId；开笔记请求按pane generation；旧请求不覆盖新选择 |
| `mergeSync(shell,payload,dirty,tombstones)` | 纯函数返回新shell及需重新取正文的ID | full快照完成前不删除未出现项；deletion按cursor；dirty正文不被覆盖 |
| `SessionState` | status/user/site/authError；load/login/completeTotp/register/logout | 切账号递增epoch，取消旧加载并隔离缓存 |
| `SettingsState` | persisted/current/pendingPatch/error；load/update/flush | 保存成功只确认对应generation；失败不回滚更晚修改 |
| `UiState` | panes/layout/activePane/view/filter/selection/recent/panel/toasts | 窗格关闭不删笔记；mobile/editor返回路径明确 |
| `OrganizeActions` | mutationsByEntity；createFolder/patchFolder/removeFolder/renameTag/removeTag | 单实体串行提交；失败只回滚本mutation涉及字段 |

保存状态：dirty→persisting→saved-local(queued)→synced；persisting失败→failed（保留文本）；queued在重连后确认。不要用单个online布尔值判断所有请求是否成功。Web editContent立即调用持久化接缝，网络合并由HttpBackend完成；桌面可由NotesState防抖但离开/退出强制flush。

元数据乐观更新保存before+patch+mutationId；服务器响应过期时只推进已知基线，叠加仍在pending的补丁。purge/emptyTrash必须先确认正文已本地安全，Web还必须处理未回放正文，不直接丢弃outbox。无rev的标签/文件夹按接口响应刷新完整相关集合。

## 11. 契约与验证

`backendContractCases` 用真实Backend和隔离库/账号执行：创建→读相同源文、成功修改rev推进、软删/恢复/清空后墓碑、标签/文件夹过滤、附件哈希、设置持久化。并发冲突按明确后端语义分支验收：底层HTTP API与Rust Library都拒绝陈旧rev；Web正文outbox会按已定策略rebase且远端旧版本进入历史，Desktop GUI/MCP直接conflict并保留缓冲。不能要求Web端口取消原有离线恢复以满足错误的通用测试。

FakeBackend仅用于状态错误/延迟/乱序测试，不能作为两种真实后端通过的证据。至少做一次浏览器真实HTTP和真实Tauri IPC往返。行为测试覆盖语言切换、abort后旧响应、quota失败、双窗格不同撤销历史、对话框键盘返回焦点。

## 12. 已裁决设计问题

1. 全局工具版本在S0收敛，不使用两个Vitest运行器加载同一场景文件。
2. 只有纯文本patch离线持久；queued包含writeId；写入通知并入ChangeFeed。
3. BackendSession仅在客户端扩大attachmentStorage为local，HTTP SiteInfo不改。
4. cancellation/timeout/invalid_response各有码，取消不变成网络离线。
5. 不承诺单JSON夹具可证明协议等价，真实操作结果加边界测试才是验收。
6. 共享UI使用packages/app，不再跨宿主拷贝两份组件；平台例外通过HostExtensions。
7. 日志是排障设施，不扩大成遥测服务；不存笔记或凭据。
