# 45 规划重构设计：Aether 依赖收口与 AutoNote 边界优化

> 状态：规划；本文件只定义重构边界、顺序和验收，不代表实现完成。
> 依据：44 工程评审、24 Aether 接入方案、25 Aether 迁移任务清单、04 工程规范。

## 1. 目标

1. 将 AutoNote 的 Web、共享 App、桌面 UI、Rust crates 和 Tauri plugin 统一固定到 Aether v0.1.1 发布提交。
2. 删除本地 Aether path/link 覆盖，确保本地和 CI 验证的是同一不可变依赖。
3. 保持 AutoNote 领域边界、授权、数据库、Writing 安全门、MCP 工具和 Web HTTP 合同不变。
4. 在升级稳定后，降低 Provider、Relay、Native 组合根和 Skill runner 的职责复杂度。
5. 只对修改路径补运行时校验和行为测试，不进行无关全仓重写。

## 2. 固定版本

目标提交：

```text
c3c3c9280f2dcacb60d2188537b54be86a099ddd
```

该提交对应 Aether `v0.1.1`。当前远程 `main` `1f5392a...` 相对该版本只有发布记录变化，不作为浮动依赖。

受影响文件：

```text
web/package.json
packages/app/package.json
desktop/package.json
desktop/src-tauri/Cargo.toml
pnpm-workspace.yaml
pnpm-lock.yaml
desktop/src-tauri/Cargo.lock
```

完整树不得保留相邻 `../Aether` 的 pnpm override、Cargo `[patch]` 或 path 替换。Aether UI `erasableSyntaxOnly` 缺陷在上游发布 patch 前只允许使用最小、可审阅、可删除的补丁，不关闭严格类型检查。

## 3. 目标边界

```text
AutoNote 产品层
  roles / note context / Writing / library.db / D1 / R2 / MCP domain tools
        ↓ HostAdapter / HTTP ports / Tauri ports
Aether 公共层
  contracts / core / providers / chat / images / MCP / skills / observability
        ↓ platform adapters
Web Worker / Tauri Native
```

禁止：Aether 访问 `library.db`；AutoNote 复制 Provider/Chat/MCP 协议；业务 MCP 绕过 `note-core`；Web 直接替换为不具备 AutoNote 授权语义的通用 adapter。

## 4. 重构切片

### R0：依赖收口

- 统一四处 TS 与十处 Rust Aether revision。
- 删除本地覆盖。
- 重新生成 pnpm/Cargo lock。
- 修复或临时记录 Aether UI 源码兼容补丁。

### R1：Provider 拆分

将 `web/src/worker/ai/providers.ts` 按职责拆分为内部模块；唯一入口继续由 `index.ts` 或原公开模块导出。保持 key 轮换、exhausted 状态、CAS、probe fallback、reasoning 校验和 model resolution 行为。

### R2：Relay 拆分

将 relay 认证、输入解析、上游请求、SSE/响应流和路由拆分。所有凭据脱敏、redirect 拒绝、body 限制、JWT/JWKS、协议映射和失败重试语义必须保持。

### R3：Native 组合根拆分

保留 `src/lib.rs` 为唯一组合根；提取状态、Store 打开、Aether runtime 装配和关闭流程。不得把业务逻辑移入 Tauri command，不得改变 data root 或数据库所有权。

### R4：Skill runner 拆分

按 revision snapshot、输入验证、进程树、输出限制和取消拆分。每个 run 只使用受理时的 skill revision；unknown 不自动重放；临时目录始终清理。

### R5：图像与校验收口

对照 Aether Images contract，评估删除重复协议编码的最小范围。宿主继续拥有公网地址检查、R2 私有存储、审批/operation、10 MiB 限制和未知副作用处理。只在被修改的 Worker 入口为数据库 JSON 增加 schema parse。

## 5. 顺序和依赖

```text
R0 → R1 → R2 → R3 → R4 → R5
```

R1/R2/R3 可在 R0 完成并验收后分别实施，但根 lock、Cargo workspace、组合根文件只能由一个集成者串行修改。R5 依赖 Aether 版本稳定和图像行为回归。

## 6. 验收合同

### R0

- 所有 Aether 依赖只指向同一 v0.1.1 commit。
- lockfile 不含旧 revision 或本地 path override。
- `pnpm install --frozen-lockfile` 和 `cargo metadata --locked` 通过。

### Web

```sh
pnpm run app:check
pnpm run web:check
pnpm run web:test
pnpm run web:build
```

Worker 改动另跑临时实例 e2e；不得把单测代替真实 SSE/快照/取消/图像行为。

### Native

```sh
pnpm --dir desktop exec desktop-kit cargo check --workspace --all-targets --locked
pnpm --dir desktop exec desktop-kit cargo test -p autonote --lib chat_context_tests --locked
pnpm --dir desktop exec desktop-kit cargo test -p autonote --lib skill_runner_tests --locked
pnpm --dir desktop exec desktop-kit cargo test -p note-mcp --test aether_server --locked
pnpm --filter autonote-desktop desktop:verify
```

需要真实窗口、重启、隔离 data、MCP HTTP、凭据持久化和 Writing 写回。Windows 结果不得外推 macOS/Linux。

### 安全不变量

- 不记录 key、token、Authorization、正文、模型输出和完整上游错误。
- cancel/unknown 不伪造成 completed。
- 外部副作用未知时不自动重放。
- CAS、scope、Origin、noteId、Writing generation/rev 安全门保持。

## 7. 回退

升级前停止写入并备份完整 data 目录、Aether lock、AutoNote commit 和恢复所需系统密钥条件。回退必须整体恢复 AutoNote 提交、Aether revision 和两套 lock，不混用新旧运行时。
