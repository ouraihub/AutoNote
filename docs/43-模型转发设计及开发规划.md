# 43 模型转发设计及开发规划

> 2026-10-24 草案，待确认。本期只做 Web（`autonote.ouraihub.com`），桌面以后再做（§10）。

## 1. 目标

- AutoNote 已经有的模型服务配置（服务商 → 线路 → 密钥 → 模型）对外提供一个 OpenAI / Anthropic 兼容的转发地址。本地 omp、GitHub Actions 里的 agent、其他兼容客户端都通过它调模型，真实密钥只保存在 AutoNote 里。
- 每条线路可以单独选择密钥的使用方式：**轮流使用**或**用完再换**，两种都支持，由用户在线路设置里选择。新建线路默认"轮流使用"，和现在的行为一样，已有线路升级后也不变。这个设置对 AutoNote 自己的 AI 对话和转发同样生效。

不做的事：协议转换（OpenAI ↔ Anthropic）、模型别名、请求改写。线路支持什么协议，转发就只转这种协议。

## 3. 密钥使用方式

`ai_endpoints` 新增 `key_strategy`：`round_robin`（轮流使用）或 `fill_first`（用完再换），在线路设置里选择。新建线路和迁移前已有的线路都默认 `round_robin`，所以不改设置的用户行为不变。

| | 轮流使用 `round_robin` | 用完再换 `fill_first` |
| --- | --- | --- |
| 起点 | 每次请求从上一次的下一个密钥开始（现有的内存游标） | 永远从第一个开始 |
| 换下一个 | 401 / 403 / 429（同 docs/34 §3.4） | 401 / 402 / 403 / 429；或 400 / 5xx 且错误内容含额度类字样（§3.1） |
| 失败后 | 不做标记，下次照常参与轮流 | 标记为"已用完"，到恢复时间之前跳过 |
| 适合 | 几个额度充足的密钥分摊限流 | 很多个小额度密钥，一个用完换一个 |

两种方式都只在上游还没开始返回内容时切换。流式内容开始后再出错，原样交给调用方。

**怎么选**：

- **用完再换**：适合很多个小额度、一次性额度的密钥。同一个会话的连续请求打在同一个密钥上，上游的提示词缓存能命中，长对话和 agent 运行更省钱也更快；到后期，前面的密钥用完了，后面的密钥额度还完整。
- **轮流使用**：适合几个额度充足、但有频率限制的密钥。请求平均分到每个密钥上，不容易触发限流；能同时并发的请求也更多。
- 有效期较短、到期作废的额度（比如按月清零），用"用完再换"可能让排在后面的密钥用不完就过期。遇到这种情况，选"轮流使用"，或者把快到期的密钥排在前面。

### 3.1 已用完的判定与恢复（仅 `fill_first`）

先区分"暂时限流"和"额度用完"，两者处理不同：

| 情况 | 判定 | 处理 |
| --- | --- | --- |
| 暂时限流 | 429，且响应里没有额度类字样 | 这个请求换下一个密钥；当前密钥冷却 `Retry-After`，没有就冷却 60 秒，然后回到原来的位置 |
| 额度用完 | 402；或者 401 / 403；或者 400 / 429 / 5xx，且响应里有额度类字样 | 标记"已用完"，24 小时后自动恢复 |

其余规则：

- 额度类字样：`quota`、`insufficient`、`balance`、`billing`、`exceeded`、`credit`、`额度`、`余额`、`用尽`、`不足`、`过期`。只在失败响应的前 4 KB 中查找，不区分大小写。
- `ai_endpoint_keys` 新增 `exhausted_until INTEGER`（毫秒时间戳）和 `exhausted_reason TEXT`（如 `HTTP 429`、`HTTP 400 余额不足`，截断到 120 个字符）。暂时限流的冷却和已用完共用这两列，只是 `exhausted_until` 不同（冷却时间或 24 小时），所以冷却同样跨请求、跨 Worker 实例生效，不放内存。
- 恢复：已用完的密钥 24 小时后自动重新参与，暂时限流的密钥按上表冷却；界面上也可以手动「恢复」。
- 线路的密钥全部已用完时，返回 `rate_limited`（`reason: keys_exhausted`），信息写明"线路 X 的密钥全部用完，最早 <时间> 恢复"。Worker 不知道用户时区，时间用 ISO 8601 UTC。
- 网络错误和超时不算用完：换下一个密钥重试一次，但不做标记。

D1 是强一致的。标记（包括冷却）写入后，同一用户的其他请求马上就能看到，不会每次都先撞一下已经用完或正在冷却的密钥。`exhausted_until` 过了就自动重新参与，不需要清理任务。

## 4. 转发接口

| 路由 | 说明 |
| --- | --- |
| `POST /relay/v1/chat/completions` | 协议 `openai-chat` |
| `POST /relay/v1/responses` | 协议 `openai-responses` |
| `POST /relay/v1/messages` | 协议 `anthropic-messages` |
| `GET /relay/v1/models` | 访问密钥所属用户下所有启用的模型，用 OpenAI `models` 列表格式返回，每个模型附带协议。omp 的 `discovery: openai-models-list` 可以用它自动发现模型 |
| `POST /relay/github/token` | GitHub Actions 用 OIDC 令牌换临时访问密钥（§5.2） |

**处理一个请求**：

1. 校验访问密钥（`Authorization: Bearer` 或 `x-api-key`），得到所属用户。
2. 读请求体里的 `model`。在这个用户的全部服务商里，先按服务商顺序、再按线路顺序，挑出满足条件的线路：已启用、协议与路径一致、模型列表里有这个 `model`。一条都没有就返回 404，并列出可用模型。
3. 从第一条线路开始，按这条线路的密钥使用方式选密钥（§3）。出站地址同样要过 `addressAllowed`。换下一条匹配线路的条件：这条线路被地址规则拦下、没有可用密钥（全部暂停或没配），或者它的密钥都试过、最后一个失败是密钥问题（401 / 402 / 403 / 429，或带额度类字样）。两种使用方式都按这个规则换线路。全部线路都不行才返回错误。所以同一个模型配在几个中转站上，前一个用完就自动用后一个。
   不同服务商下有同名模型时，可以写成 `服务商名/模型名`，指定只在这个服务商里找。模型 id 本身也可能带 `/`（如 `openai/gpt-6.1-sol`），所以先按完整的模型名找；找不到，并且 `/` 前面正好是某个服务商的名称，再按 `服务商名/模型名` 解释。
4. 去掉所有入站认证头，只保留 `anthropic-version`、`anthropic-beta`、`content-type`、`accept`；换上 `authHeaders(protocol, key)` 和线路的自定义请求头。请求体原样转发，只有一个例外：按 `服务商名/模型名` 选到的线路，把 `model` 改回上游自己的模型 id（去掉 `服务商名/` 前缀），其他字段不动。
5. 上游返回 2xx：把状态、`content-type` 和响应体流原样返回。失败时按 §3 决定换下一个密钥或下一条线路；不换的失败（如 400 参数错误、没有额度字样的 5xx）把上游的状态和响应体原样返回，客户端看到的就是上游的错误。网络错误和超时返回 502。
6. 记录访问密钥的 `last_used_at` 和当天请求数，不记密钥和请求内容。

**错误格式**：转发自己产生的错误用 Anthropic / OpenAI 客户端都能识别的格式 `{"type":"error","error":{"type":"…","message":"…"}}`。`type` 取值：`authentication_error`（401，访问密钥无效、已吊销或过期）、`relay_paused`（503）、`not_found_error`（404，没有匹配的模型，信息里列出可用模型）、`invalid_request_error`（400 / 413，请求体不是 JSON、缺 `model`、超过 10 MB）、`rate_limit_error`（429，超过并发上限，或全部线路的密钥都已暂停，信息里写最早恢复时间）、`permission_error`（403，GitHub 仓库或工作流没有登记）、`api_error`（502）。

**限制**：

- 请求体最大 10 MB。
- 每个访问密钥最多同时 8 个请求，超出返回 429。不复用 AI 对话的 `acquireSlot`，它只允许 2 个并发，agent 会开子任务并行。计数在 Worker 实例内存里，所以是每个实例 8 个；要全局精确限制时改用 Durable Object。流式响应传完才释放名额。
- 不经过登录会话，不读写笔记数据，只能调用这个用户自己配置的模型。

**客户端不用重启**：客户端只保存访问密钥和转发地址。每个请求都会重新读一次 D1 里的线路和密钥，所以在 AutoNote 里加密钥、删密钥、调整顺序、切换使用方式，或者某个密钥用完被跳过，下一个请求就生效。正在运行的 omp 不用重启，同一个会话也不用中断。只有更换访问密钥本身，才需要改客户端配置。

**暂停与启用**：设置「模型转发」最上方有一个总开关，默认关闭，要你手动启用后转发才开始工作。

- 暂停时，`/relay/v1/*` 和 `/relay/github/token` 一律返回 503，错误类型 `relay_paused`，信息是"模型转发已暂停，请在 AutoNote 设置中启用"。访问密钥和已登记的仓库都保留，重新启用后可以直接用，不用重新生成。
- 切换后下一个请求立即生效，因为每个请求都会读一次开关。已经在传输中的流式响应不会被切断，会跑完为止。
- 暂停期间 GitHub Actions 在换取令牌这一步就会拿到 503。
- 只影响转发，AutoNote 自己的 AI 对话不受影响。
- 开关按用户存在 `app_meta` 的 `relay_enabled:<用户 id>`，不加新列。不放 `users.settings`：保存设置时只保留已知字段，`relayEnabled` 会在改主题等操作时被丢掉。

## 5. 访问凭据

### 5.1 访问密钥

新表 `relay_access_keys`，写法同 `mcp_api_keys`。新表直接用 `CREATE TABLE IF NOT EXISTS` 建，不占迁移版本：

```sql
CREATE TABLE IF NOT EXISTS relay_access_keys (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL,
  name TEXT NOT NULL, key_hash TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL, last_used_at INTEGER, expires_at INTEGER, revoked_at INTEGER,
  day TEXT, day_requests INTEGER NOT NULL DEFAULT 0  -- day 为 UTC 日期，跨天第一次请求时归零
)
```

- 格式为 `anr_` 加 32 字节随机串（base64url），只在创建时显示一次。
- 每个用户最多 20 个有效密钥（未吊销且未过期）。手动建的密钥不过期；GitHub 换来的 2 小时后过期（§5.2）。
- 每次校验通过就更新 `last_used_at` 和当天请求数，暂停期间的请求也计数（它通过了校验）。
- 吊销或过期满 1 天的行，每天定时任务清理。
- 访问密钥可以使用所属用户的全部服务商。新增服务商后，不用重新生成访问密钥，下一个请求就能用。
- 管理接口（登录会话，只限 owner，同 AI 设置）：`GET /api/relay`（开关、转发地址、密钥列表、已登记仓库）、`PUT /api/relay {enabled}`、`POST /api/relay/keys {name}`（返回一次性的 `token`）、`DELETE /api/relay/keys/:id`、`POST /api/relay/repos {repo, workflow}`、`DELETE /api/relay/repos/:owner/:name`。

### 5.2 GitHub Actions

- 在设置里登记允许使用转发的仓库，以及这个仓库里允许换密钥的工作流（新表 `relay_github_repos(repo TEXT PRIMARY KEY, user_id, workflow, created_at)`）。`workflow` 是完整路径 `owner/repo/.github/workflows/文件.yml`，可以是别的仓库里的可复用工作流。一个仓库只能被一个用户登记，别的用户再登记返回 409；同一用户重复登记就更新工作流。
- Actions 申请 GitHub OIDC 令牌，`audience` 为本站地址（`https://autonote.ouraihub.com`），然后调用 `POST /relay/github/token {token}`。Worker 用 GitHub 的 JWKS（`https://token.actions.githubusercontent.com/.well-known/jwks`）验 RS256 签名，并检查：
  - `iss` 是 `https://token.actions.githubusercontent.com`，`aud` 是本站，`exp` 未过；
  - `repository` 已登记；
  - `job_workflow_ref` 是登记的工作流（`<workflow>@<ref>`）。同一仓库里的其他工作流换不到密钥。
- 检查通过、并且登记这个仓库的用户已启用转发后，签发一个 `relay_access_keys` 行，`expires_at` 为 2 小时后，名称是"GitHub 仓库名 运行号"。之后的请求和普通访问密钥走同一条校验路径，不需要新的签名密钥。
- 返回 `{key, expiresAt, models}`：访问密钥、过期时间，以及全部可用模型和各自的协议（同 `GET /relay/v1/models` 的 `data`），调用方用它生成客户端配置。
- 失败：令牌格式、签名、`aud`、`exp` 或工作流不对返回 401，仓库没登记返回 403，转发已暂停返回 503。

## 6. 界面

**Aether `packages/ui/src/providers/`**（Web 与桌面共用组件）：

- `EndpointPanel`：新增「密钥使用方式」选择：轮流使用 / 用完再换。只有当宿主返回了 `keyStrategy` 时才显示。桌面这一期不返回，所以不显示。
- `EndpointKeysDialog`：用完再换模式下，每个密钥显示「已用完 · 原因 · 恢复时间」，并提供「恢复」按钮。
- DTO（`crates/aether-providers/src/dto.rs` 为准，`pnpm kit:dto` 生成）：
  - `Endpoint.keyStrategy: KeyStrategy | null`；`EndpointSave.keyStrategy?: KeyStrategy`；
  - `EndpointKey.exhaustedUntil: number | null`、`exhaustedReason: string | null`；
  - `EndpointKeySave.restore?: boolean`。
  - 桌面 store 这一期不存这些字段，返回 `null`，忽略写入。
- i18n：`en.ts`、`zh-CN.ts` 同时加。

**AutoNote 设置「模型转发」**（只在 Web 显示，位置同 MCP 密钥设置）：

- 总开关：启用 / 暂停转发，显示当前状态。暂停时页面顶部有醒目提示。
- 访问密钥：新建（写名称）、列表（最后使用时间、今天请求数、过期时间）、吊销。
- GitHub 仓库：增删允许使用转发的 `owner/repo`，每个仓库填一个允许的工作流路径。
- 接入说明：显示转发地址，以及生成好的 omp `models.yml` 片段（`discovery: openai-models-list` 自动列出全部模型），可以一键复制。

## 7. 客户端接入

- 本地 omp：`models.yml` 里加一个 provider，`baseUrl` 为转发地址，`apiKey` 为访问密钥，`discovery: openai-models-list`。设置页直接生成这段配置。
- GitHub Actions：job 加 `id-token: write`，用 `actions/github-script` 的 `core.getIDToken('<本站地址>')` 取令牌，POST 到 `/relay/github/token`，用返回的 `key` 和 `models` 生成客户端配置。仓库里不再需要保存模型密钥。
- 具体哪个工作流怎么接入，写在那个工作流自己的仓库里，不写在本文。

## 8. 安全

| 风险 | 处理 |
| --- | --- |
| 访问密钥泄露 | 可以吊销；GitHub 换来的密钥 2 小时后过期；只能调用模型，不能读写笔记数据；界面上能看到每个访问密钥的用量 |
| 用转发访问内网 | 出站地址走 `addressAllowed`，规则和 AI 对话相同 |
| 仓库里别的工作流换密钥 | 检查 `job_workflow_ref` 必须是登记的那个工作流 |
| 上游错误里带回敏感信息 | 只透传上游的状态和响应体，不附带我们的日志；日志不记录密钥和请求内容 |
| 额度被刷 | 每个访问密钥限 8 个并发；界面显示每个访问密钥的用量 |

## 9. 开发顺序与验收

1. **Aether**：DTO 字段、`EndpointPanel` 选择、`EndpointKeysDialog` 状态和恢复、i18n。跑通 Aether 的 `pnpm run ci` 后推送。
2. **AutoNote Worker**：
   - 迁移 v29（`key_strategy`、`exhausted_*`）；转发的两张新表用 `CREATE TABLE IF NOT EXISTS` 直接建；
   - `providers.ts` 按策略选密钥，`withKeys` 按策略判定是否换下一个；
   - 补单元测试，覆盖两种策略、已用完的判定、恢复时间、全部用完、流式开始后不切换。
   - 进展（10-24）：已实现。同一次请求的多轮工具调用共用一个密钥池，暂停的密钥当场移出；上游在第一段内容前断开算网络错误，换下一个密钥重试。
3. **转发接口和访问凭据**：`/relay/v1/*`、访问密钥、GitHub OIDC 换取，加单元测试。
   - 进展（10-24）：已实现（`web/src/worker/ai/relay.ts`、`routes/relay.ts`，测试 `web/tests/relay.test.ts`）。
4. **设置界面「模型转发」**。
5. **集成验证**：
   - 在 AutoNote 的 4 处升级 Aether 引用，跑 `pnpm run ci` 和 e2e；
   - 本地起两个回环假上游，第一个返回"余额不足"，确认 AI 对话和转发都会落到第二个；界面显示"已用完"，恢复后重新可用；轮流使用模式下行为和现在一样。
6. **上线**：开 PR 合并后部署到 `autonote.ouraihub.com`，部署前再请你确认一次。

GitHub Actions 侧的接入不在本仓库的开发范围里。

## 10. 桌面版（以后）

- `aether-providers` 的 store 加迁移，持久化 `key_strategy` 和 `exhausted_*`，`rotated_keys` 按策略选密钥。这样桌面 AI 对话也能选"用完再换"。
- 桌面上的转发地址要不要做（本机的 omp 走桌面版的密钥），等有需要时再定。

## 11. 已确定

1. 两种密钥使用方式都支持，每条线路单独选择；默认"轮流使用"，已有线路不受影响。
2. 访问密钥可以使用全部服务商；用 `服务商名/模型名` 可以指定某一个服务商。
3. 转发有总开关，默认关闭；暂停后立即拒绝新请求，不影响 AutoNote 自己的 AI 对话。
4. GitHub 换取按登记的仓库和工作流放行，不绑定任何特定的工作流仓库。
