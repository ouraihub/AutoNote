# 43 模型转发设计及开发规划

> 2026-10-24 草案，待确认。本期只做 Web（`autonote.ouraihub.com`），桌面以后再做（§10）。

## 1. 目标

- AutoNote 已经有的模型服务配置（服务商 → 线路 → 密钥 → 模型）对外提供一个 OpenAI / Anthropic 兼容的转发地址。本地 omp、GitHub Actions 里的 agent、其他兼容客户端都通过它调模型，真实密钥只保存在 AutoNote 里。
- 每条线路可以单独选择密钥的使用方式：**轮流使用**或**用完再换**，两种都支持，由用户在线路设置里选择。新建线路默认"轮流使用"，和现在的行为一样，已有线路升级后也不变。这个设置对 AutoNote 自己的 AI 对话和转发同样生效。

不做协议转换（OpenAI ↔ Anthropic）或任意模型别名。线路支持什么协议，转发就只转这种协议；唯一的请求改写是按服务商限定选路时去掉 `model` 的服务商前缀（§4）。

## 3. 密钥使用方式

`ai_endpoints` 新增 `key_strategy`：`round_robin`（轮流使用）或 `fill_first`（用完再换），在线路设置里选择。新建线路和迁移前已有的线路都默认 `round_robin`，所以不改设置的用户行为不变。

| | 轮流使用 `round_robin` | 用完再换 `fill_first` |
| --- | --- | --- |
| 起点 | 每次请求从上一次的下一个密钥开始（现有的内存游标） | 永远从第一个开始 |
| 换下一个 | 401 / 403 / 429（同 docs/34 §3.4） | 401 / 402 / 403 / 429；或 400 / 5xx 且错误内容含扣费类或额度类字样（§3.1） |
| 失败后 | 不做标记，下次照常参与轮流 | 标记为"已用完"，到恢复时间之前跳过 |
| 适合 | 几个额度充足的密钥分摊限流 | 很多个小额度密钥，一个用完换一个 |

两种方式都只在上游还没开始返回内容时切换。流式内容开始后再出错，原样交给调用方。

**怎么选**：

- **用完再换**：适合很多个小额度、一次性额度的密钥。同一个会话的连续请求打在同一个密钥上，上游的提示词缓存能命中，长对话和 agent 运行更省钱也更快；到后期，前面的密钥用完了，后面的密钥额度还完整。
- **轮流使用**：适合几个额度充足、但有频率限制的密钥。请求平均分到每个密钥上，不容易触发限流；能同时并发的请求也更多。
- 有效期较短、到期作废的额度（比如按月清零），用"用完再换"可能让排在后面的密钥用不完就过期。遇到这种情况，选"轮流使用"，或者把快到期的密钥排在前面。

### 3.1 已用完的判定与恢复（仅 `fill_first`）

先区分"暂时限流"和"额度用完"，两者处理不同：

| 情况 | 判定 | 处理 |
| --- | --- | --- |
| 暂时限流 | 429，且响应里没有扣费类字样（"额度"类字样也算限流，见下） | 这个请求换下一个密钥；当前密钥冷却 `Retry-After`，没有就冷却 60 秒，然后回到原来的位置 |
| 额度用完 | 402；或者 401 / 403；或者 429 且有扣费类字样；或者 400 / 5xx 且有扣费类或额度类字样 | 标记"已用完"，24 小时后自动恢复 |

其余规则：

- 扣费类字样：`insufficient`、`balance`、`billing`、`credit`、`余额`、`欠费`、`用尽`、`不足`、`过期`。额度类字样：`quota`、`额度`。只在失败响应的前 4 KB 中查找，不区分大小写。
- 不用 `exceeded`、`limit` 这类词判定：`rate limit exceeded`、`Quota exceeded … per minute` 是普通限流，只冷却，不暂停 24 小时。所以 429 只看扣费类字样。
- `ai_endpoint_keys` 新增 `exhausted_until INTEGER`（毫秒时间戳）和 `exhausted_reason TEXT`（如 `HTTP 429`、`HTTP 400 余额不足`，截断到 120 个字符）。暂时限流的冷却和已用完共用这两列，只是 `exhausted_until` 不同（冷却时间或 24 小时），所以冷却同样跨请求、跨 Worker 实例生效，不放内存。
- 暂停按本次实际尝试的密钥记录 ID 写入，不按解密后的字符串查最后一条记录；即使历史数据含重复密钥，也逐条正确暂停，不让已耗尽记录在后续请求重新出现。
- 恢复：已用完的密钥 24 小时后自动重新参与，暂时限流的密钥按上表冷却；界面上也可以手动「恢复」。
- 线路的密钥全部已用完时，返回 `rate_limited`（`reason: keys_exhausted`），信息写明"线路 X 的密钥全部用完，最早 <时间> 恢复"。Worker 不知道用户时区，时间用 ISO 8601 UTC。
- 网络错误和超时不算用完：换下一个密钥重试一次，但不做标记。
普通限流的 `Retry-After` 支持秒数或 HTTP 日期，冷却最长 24 小时。绘图调用每个密钥尝试独立计时；绘图线路全部暂停只使绘图工具调用失败，不阻断仍有可用聊天线路的对话。请求内暂停的密钥立即移出后续轮次候选。

暂停状态要马上对其他请求可见。Worker 直接用 `env.DB`，不用 D1 Sessions API，按 Cloudflare 文档，这种写法的读写都只走主库，不会读到落后的只读副本，所以标记（包括冷却）写入后，同一用户的其他请求马上就能看到，不会每次都先撞一下已经用完或正在冷却的密钥。以后如果开启只读副本（`withSession`），选密钥和写暂停这两步必须用 `withSession('first-primary')`，不能用默认的 `first-unconstrained`。`exhausted_until` 过了就自动重新参与，不需要清理任务。

## 4. 转发接口

| 路由 | 说明 |
| --- | --- |
| `POST /relay/v1/chat/completions` | 协议 `openai-chat` |
| `POST /relay/v1/responses` | 协议 `openai-responses` |
| `POST /relay/v1/messages` | 协议 `anthropic-messages` |
| `GET /relay/v1/models` | 仅列出启用服务商下 `model_type = 'chat'` 的模型，OpenAI `models` 列表格式，每项附带协议。同一模型同一协议只按服务商顺序给第一家保留原始 id，后续不同服务商使用 `服务商名/模型名`；同一服务商多条线路不重复。服务商重名时限定名选择顺序最前的同名服务商，不承诺可用名称区分重名服务商。完整原始 id 优先于限定名解释。 |
| `POST /relay/github/token` | GitHub Actions 用 OIDC 令牌换临时访问密钥（§5.2） |

**处理一个请求**：

1. 校验访问密钥（`Authorization: Bearer` 或 `x-api-key`），得到所属用户。
2. 读请求体里的 `model`。在这个用户的全部启用服务商下，先按服务商顺序、再按线路顺序，挑选协议与路径一致且包含该对话模型的线路。线路、模型自身没有启用字段。一条都没有就返回 404，并列出可用模型。
3. 每条线路按 §3 选密钥，出站地址走 `addressAllowed`。地址被拦下或没有可用密钥时跳过线路。轮流使用仅在 401 / 403 / 429 时继续尝试本线路下一个密钥；用完再换按 §3.1 继续尝试。若停止尝试的失败属于密钥问题（401 / 402 / 403 / 429 或 §3.1 的用完判定），允许继续下一条匹配线路，即使轮流使用因 402 提前停止、没有尝试剩余密钥。参数错误和不含额度/扣费字样的 5xx 不换线路；网络错误只按 §3.1 在本线路内重试，不换线路。
   可以用 `服务商名/模型名` 指定服务商；先查完整原始模型 id，再解释限定名。服务商重名时只选顺序最前的同名服务商下的匹配线路。
4. 只保留入站 `anthropic-version`、`anthropic-beta`、`content-type`、`accept`，不转发入站认证头或 Cookie；设置线路自定义头和 `authHeaders`，再覆盖保留的客户端头，所以客户端的 Anthropic 版本和 beta 优先。原始模型 id 请求保持请求体字节不变；限定名选路只把 `model` 改回上游原始 id，其他字段不变。
5. 2xx 响应透传状态、`content-type` 和响应体流，流开始后不切换。非切换错误或所有尝试结束时，返回最后一次上游响应的状态和内容，但必须遮蔽其中的真实密钥。若所有候选线路均因密钥暂停而跳过，返回 429 `rate_limit_error` 和所有线路中最早恢复时间。没有上游响应的网络/配置错误返回 502；客户端取消终止请求。
6. 记录访问密钥的 `last_used_at` 和当天请求数，不记密钥和请求内容。

**错误格式**：转发产生的错误统一为 `{"type":"error","error":{"type":"…","message":"…"}}`：`authentication_error`（401，凭据/令牌/工作流/受信来源无效）、`relay_paused`（503）、`not_found_error`（404，未知路由或模型）、`invalid_request_error`（400 / 413，非法或超大请求；409，手动密钥达到数量上限）、`rate_limit_error`（429，单实例并发限制或所有候选线路均暂停）、`permission_error`（403，仅仓库未登记）、`api_error`（502，网络、超时、缺配置；500，内部故障）。不切换的上游错误保留上游状态和格式，但遮蔽真实密钥。

**限制**：

- 请求体最大 10 MB。
- 每个访问密钥在单个 Worker 实例内最多同时 8 个请求，流式传输结束或取消后释放。这是单实例软限制，不是跨实例全局防刷保证；不复用只允许 2 并发的聊天 `acquireSlot`。访问密钥仅交给可信使用方，泄露时吊销或暂停转发；需要强全局配额时另用 Durable Object，不能把当前计数当硬额度。
- 不经过登录会话，不读写笔记数据，只能调用这个用户自己配置的模型。

**客户端不用重启**：客户端只保存访问密钥和转发地址。每个请求都会重新读一次 D1 里的线路和密钥，所以在 AutoNote 里加密钥、删密钥、调整顺序、切换使用方式，或者某个密钥用完被跳过，下一个请求就生效。正在运行的 omp 不用重启，同一个会话也不用中断。只有更换访问密钥本身，才需要改客户端配置。

**暂停与启用**：设置「模型转发」最上方有一个总开关，默认关闭，要你手动启用后转发才开始工作。

- 暂停时，`/relay/v1/*` 和 `/relay/github/token` 一律返回 503，错误类型 `relay_paused`，信息是"模型转发已暂停，请在 AutoNote 设置中启用"。访问密钥和已登记的仓库都保留，重新启用后可以直接用，不用重新生成。
- 切换后下一个请求立即生效，因为每个请求都会读一次开关。已经在传输中的流式响应不会被切断，会跑完为止。
- 暂停期间 GitHub Actions 在换取令牌这一步就会拿到 503。
- 只影响转发，AutoNote 自己的 AI 对话不受影响。
- 开关按用户存在 `app_meta` 的 `relay_enabled:<用户 id>`，不加新列。不放 `users.settings`：保存设置时只保留已知字段，`relayEnabled` 会在改主题等操作时被丢掉。

## 5. 访问凭据

### 5.1 访问密钥

新表通过版本化迁移 v30 创建；同时登记必须存在的表、列和索引，升级与新库初始化均验证结构。后续结构变更继续新增版本化迁移，不靠 `IF NOT EXISTS` 隐式升级。

```sql
CREATE TABLE IF NOT EXISTS relay_access_keys (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL,
  name TEXT NOT NULL, key_hash TEXT NOT NULL UNIQUE,
  created_at INTEGER NOT NULL, last_used_at INTEGER, expires_at INTEGER, revoked_at INTEGER,
  day TEXT, day_requests INTEGER NOT NULL DEFAULT 0,
  github_run TEXT  -- repo#run_id#run_attempt；手动密钥为 NULL
)
```

- 格式为 `anr_` 加 32 字节随机串（base64url），只在创建时显示一次。
- 手动密钥最多 20 个未吊销项，不过期。GitHub 临时密钥不占此上限，按仓库另限 20 个有效项（§5.2）。
- 每次校验通过就更新 `last_used_at` 和当天请求数，暂停期间的请求也计数（它通过了校验）。
- 吊销或过期满 1 天的行，每天定时任务清理。
- 访问密钥可以使用所属用户的全部服务商。新增服务商后，不用重新生成访问密钥，下一个请求就能用。
- 管理接口（登录会话，只限 owner，同 AI 设置）：`GET /api/relay`（开关、转发地址、密钥列表、已登记仓库）、`PUT /api/relay {enabled}`、`POST /api/relay/keys {name}`（返回一次性的 `token`）、`DELETE /api/relay/keys/:id`、`POST /api/relay/repos {repo, workflow, ref}`、`DELETE /api/relay/repos/:owner/:name`。

### 5.2 GitHub Actions

- `relay_github_repos` 由迁移 v30 创建，字段：`repo TEXT PRIMARY KEY`、`user_id TEXT NOT NULL`、`workflow TEXT NOT NULL`、`ref TEXT NOT NULL`、`repository_id TEXT`、`created_at INTEGER NOT NULL`。访问密钥索引覆盖用户/吊销状态、过期时间和 `github_run`；仓库表按用户索引。
- 登记 `repo`、`workflow`、`ref`：仓库 owner/name 不区分大小写；工作流 owner/name 也不区分大小写，但 `.github/workflows/文件名` 路径保留大小写。`ref` 默认 `refs/heads/main`，必须是完整受信分支或标签。
- 同一仓库只能由一个用户登记，其他用户返回 409；原用户重复登记更新工作流和 ref，保留已绑定的不可变 `repository_id`。首次成功换取原子绑定 GitHub 的 `repository_id` 声明，后续不一致一律拒绝；重新绑定必须先移除登记再添加。首次绑定前由管理员确认仓库名称当前属于预期仓库，不能把首次绑定当成历史归属证明。
- Actions 申请 GitHub OIDC 令牌，`audience` 为本站地址（`https://autonote.ouraihub.com`），然后调用 `POST /relay/github/token {token}`。Worker 用 GitHub 的 JWKS（`https://token.actions.githubusercontent.com/.well-known/jwks`）验 RS256 签名，并检查：
  - `iss` 是 `https://token.actions.githubusercontent.com`，`aud` 是本站，`exp` 未过；
  - `repository` 已登记；
  - `ref` 等于登记的受信分支。来自 PR 的运行 `ref` 是 `refs/pull/<n>/merge`，在这里就被拒；
  - `event_name` 必须是 `push`、`workflow_dispatch`、`schedule` 之一；拒绝 `pull_request`、`pull_request_target`、`workflow_run`、`issue_comment` 等其他触发来源；
  - 跑 job 的工作流取 `job_workflow_ref`，没有则取 `workflow_ref`；必须为 `<登记工作流>@<非空 ref>`，身份规则按上文规范化比较。
- 可复用工作流也要求调用方是登记仓库、受信 ref、允许事件，并由该受信 ref 中的工作流决定调用哪个可复用工作流版本。工作流维护者是受信主体，不允许运行不受信的 PR 代码。
- 换取结果有效 2 小时，名称为 GitHub 仓库名与运行号。用 `repo#run_id#run_attempt` 标识一次运行尝试；重复换取原子吊销该尝试之前的密钥再签新密钥，不返回或存储旧明文。签发前清理该用户已过期密钥；同仓库达到 20 个有效临时密钥时原子吊销最旧项，为新项让位，不影响手动密钥。并发签发、撤销和插入在同一 D1 batch 事务中完成。
- 返回 `{key, expiresAt, models}`：访问密钥、过期时间，以及全部可用模型和各自的协议（同 `GET /relay/v1/models` 的 `data`），调用方用它生成客户端配置。
- 失败：令牌格式、签名、`aud`、`exp`、分支、事件或工作流不对返回 401，仓库没登记返回 403，转发已暂停返回 503。
- 验收：拒绝所有非允许事件、非受信 ref、其他工作流和 `repository_id` 变化；普通/可复用工作流按规则成功。重复运行尝试旧密钥失效，仓库临时密钥上限不阻塞手动密钥。

## 6. 界面

**Aether `packages/ui/src/providers/`**（Web 与桌面共用组件）：

- `EndpointPanel`：按 `ProvidersPort.keyStrategies` 显示密钥使用方式；Web 为 true，桌面为 false，桌面仍返回 round_robin。
- `EndpointKeysDialog`：用完再换模式下，每个密钥显示「已用完 · 原因 · 恢复时间」，并提供「恢复」按钮。
- DTO（`crates/aether-providers/src/dto.rs` 为准，`pnpm kit:dto` 生成）：
  - `Endpoint.keyStrategy: KeyStrategy`；`EndpointSave.keyStrategy?: KeyStrategy`；宿主是否支持修改由 `ProvidersPort.keyStrategies` 表达；
  - `EndpointKey.exhaustedUntil: number | null`、`exhaustedReason: string | null`；
  - `EndpointKeySave.restore?: boolean`。
  - 桌面 store 本期不持久化这些配置，策略返回 `round_robin`，暂停字段返回 `null`，忽略写入。
- i18n：`en.ts`、`zh-CN.ts` 同时加。

**AutoNote 设置「模型转发」**（只在 Web 显示，位置同 MCP 密钥设置）：

- 总开关：启用 / 暂停转发，显示当前状态。暂停时页面顶部有醒目提示。
- 访问密钥：新建（写名称）、列表（最后使用时间、今天请求数、过期时间）、吊销。
- GitHub 仓库：增删允许使用转发的 `owner/repo`，每个仓库填允许的工作流路径和受信分支（默认 `refs/heads/main`）。
- 接入说明按用户实际协议分别生成 provider 配置，不能给仅有 Anthropic 模型的用户生成 OpenAI API 配置。显示转发地址、`discovery: openai-models-list`，支持一键复制。

## 7. 客户端接入

- 本地 omp：`models.yml` 里加一个 provider，`baseUrl` 为转发地址，`apiKey` 为访问密钥，`discovery: openai-models-list`。设置页直接生成这段配置。
- GitHub Actions 的允许事件 job 配置 `id-token: write`，向本站 audience 申请 OIDC 令牌后换取临时密钥。`pull_request_target` 等不受支持事件不能使用此换取，包括本仓库自己的 PR 审查流程；它们继续使用独立凭据，不承诺所有工作流都无需 secret。
- 具体哪个工作流怎么接入，写在那个工作流自己的仓库里，不写在本文。

## 8. 安全

| 风险 | 处理 |
| --- | --- |
| 访问密钥泄露 | 可以吊销；GitHub 换来的密钥 2 小时后过期；只能调用模型，不能读写笔记数据；界面上能看到每个访问密钥的用量 |
| 用转发访问内网 | 出站地址走 `addressAllowed`，规则和 AI 对话相同 |
| 不受信来源换密钥 | 受信 ref、事件允许列表、登记工作流、不可变 repository_id |
| 上游错误泄露真实密钥 | 透传前遮蔽真实密钥，日志不记录请求/响应正文或凭据 |
| 凭据泄露或额度误用 | 仅可信客户端、可吊销、总暂停、临时密钥 2 小时过期、使用量可见；8 并发仅为单实例软保护，不承诺全局配额 |
