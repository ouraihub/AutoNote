# 33 模型服务设置：Cherry 交互移植与 Aether 复用能力

> 状态：设计已定，按本文实施。
> 范围：Aether `packages/ui/src/providers`（共享，Web 与桌面同时生效）+ AutoNote 宿主接入。
> 参照：Cherry `src/renderer/pages/settings/ProviderSettings/**`（截图：Fenno 页面）。

## 1. 结论

AutoNote 与 Cherry 的差距不在样式，而在**保存模型和信息层级**：

| 维度 | Cherry | AutoNote 现状 | 后果 |
| --- | --- | --- | --- |
| 保存 | 每个字段各自提交：开关立即 PATCH；密钥/地址失焦提交；增删模型立即生效；模型设置在抽屉里保存 | 整个服务商是一份草稿，任何改动都弹“有未保存的改动”，再点保存 | 用户点开关也被要求保存；改一个地址要多点两次 |
| 层级 | 标题 → API 密钥 → API 地址 → 模型；次要配置（协议、请求头、名称）收在齿轮里 | 线路卡片里铺开协议、地址、预览、密钥、模型、模型设置折叠区 | 页面长、主操作不突出 |
| 模型 | 分组卡片；行内能力标签（彩色小胶囊）+ 设置 + 移除；工具栏：折叠/搜索/筛选、同步模型、手动添加 | 分组列表 + 页面底部“模型设置”折叠区 + “获取模型”按钮 | 改单个模型参数要去页面底部 |
| 主题 | 状态色是语义色（success 绿点、开关绿轨道） | 开关用 `bg-input`，AutoNote 把 input 映射成 11% 透明的边框色 → 看不见 | 换主题时颜色无法统一控制 |

所以本次是**换保存模型 + 换层级**，数据合同（`Provider`/`EndpointSave`/`ProbeTarget`）和后端不变，只新增已实现的 `setEnabled`。

## 2. Cherry 源码中的交互逻辑（已核对）

| 文件 | 行为 | 移植 |
| --- | --- | --- |
| `ProviderSettingsPage.tsx` | 左列表 + 右详情；记住上次选中；选中项被删除时回退到第一项 | 移植选中与回退；“记住上次选中”不做（宿主无持久化需求） |
| `ProviderList/*`、`ProviderListItem.tsx` | 搜索 + 筛选菜单；行 = 头像 + 名称 + 启用绿点；hover 显示更多菜单；底部“添加服务商” | 移植；无 logo 时用首字母头像（Cherry 的 fallback）；更多菜单的“编辑/删除”放进标题齿轮对话框 |
| `ProviderHeader.tsx` + `useProviderEnable` | 名称为文本；齿轮开 API 选项；Switch 独立 PATCH，请求中禁用，失败 toast | 已实现 `setEnabled`；齿轮改为“服务商设置”（名称、删除） |
| `ApiKey.tsx` | 掩码 + 眼睛；复制/编辑/删除仅悬停或聚焦时出现（`group-hover`/`group-focus-within`）；失焦提交；失败不提示拉取模型；右侧“检测” | 移植；多密钥（每条线路多个密钥、密钥管理对话框、轮换与失败切换）见 `docs/34-线路多密钥设计及开发规划.md`；掩码中段压成 `****`；未显示时点复制先取明文（Web 需当前密码）再复制 |
| `ApiHost.tsx` | 地址输入失焦提交；标签旁“添加端点”；右侧齿轮开请求配置 | 移植；齿轮开“线路设置”（协议、请求地址预览、删除线路） |
| `ModelListHeader.tsx` | 标题 + 全部折叠 + 可展开搜索 + 能力筛选；右侧同步模型、+ | 移植 |
| `ModelListGroup.tsx` / `ModelListItem.tsx` | 组卡片，hover 出现“移除整组”；行 = 头像 + 名称 + 能力标签 + 设置 + 移除 | 移植；能力只来自 DTO，不猜 |
| `ProviderModelList` → `EditModelDrawer` | 模型参数在抽屉里改，保存后生效 | 用 Dialog 承载现有字段 |

## 3. 保存模型（核心变化）

后端仍是整份保存 `save(ProviderSave)`。前端每次“提交”发送当前整份草稿，但触发点改为字段级：

| 操作 | 触发 | 说明 |
| --- | --- | --- |
| 启用开关 | 点击 | `setEnabled(id, enabled)`，不走整份保存，不影响其它字段 |
| 名称 | 服务商设置对话框“保存” | |
| 地址 | 失焦 / Enter，且值变化 | 非 `http(s)://` 时就地提示，不发请求 |
| 协议 | 线路设置中选择即提交 | |
| 密钥 | 编辑框失焦 / Enter 且非空；删除按钮立即提交 | 三态不变：未改不发 `apiKey`，删除发 `''` |
| 模型 | 同步弹窗中每次 + / − / 全部添加 / 全部移除 / 改已选模型类型、手动添加、移除、移除整组、模型设置“保存” | 与 Cherry `onAddModels/onRemoveModels` 一致，弹窗没有“使用 N 个模型”确认按钮；探测结果之外的模型（手动添加的）保持不变 |

规则：

- **串行提交**：同一时刻只有一个请求；进行中又有新提交时，结束后用最新草稿再发一次。
- **新线路**：地址合法之前不随整份保存发送（否则后端报 `invalid_url`）。
- **回写**：成功后把服务端返回的线路 id 写回草稿（否则下次保存会重复建线路），已发送的密钥清回“保持”。
- **失败**：toast 错误，保留本地值，下次提交重试；此时切换服务商需确认放弃。
- 删除“有未保存的改动”保存栏及相关文案。

纯逻辑放 `draft.ts`（`savable`、`adopt`、`nextSlug`），配一个单元测试。

## 4. 页面结构

```text
┌───────────────┬─────────────────────────────────────────────┐
│ [🔍 搜索…  ⏷] │ easyclaude  ⚙                          [●] │
│ [e] easyclaude ●│ API 密钥                                    │
│ [F] fenno      │ [sk-y****Hv2D       (悬停:⧉ ✎ 🗑) 👁]  [检测] │
│               │ ✓ 连接正常，可用 12 个模型                  │
│               │ API 地址  添加端点        [线路 ▾ 仅多线路]  │
│               │ [https://api.easyclaude.com           ] [⚙] │
│               │ 模型 ⇕ 🔍 ⏷               [⟳ 同步模型] [+] │
│               │ ┌ ⌄ claude                           − ┐   │
│ [+ 添加服务商] │ │ (C) claude-opus-5-5   [👁][💡][🔧] ⚙ − │   │
└───────────────┴─────────────────────────────────────────────┘
```

- 左列约 15rem；`< sm` 上下堆叠；详情 `min-w-0`，长名称/地址截断，不出现横向滚动。
- 列表筛选用一个图标按钮的 Select（全部 / 已启用 / 已停用），替代三个文字按钮。
- 列表状态点：启用且有可读密钥 = success；启用但缺密钥/密钥不可读 = warning；停用 = 无点、名称降为 muted。
- 多线路：仅当线路数 > 1 时显示“线路”选择器，密钥/地址/模型都作用于所选线路；单线路时界面与 Cherry 一致。
- “检测”= 探测模型列表，只显示结果行，不打开挑选框；“同步模型”= 探测并打开挑选框。
- 无服务商：右侧空状态 + “添加服务商”。“添加服务商”弹对话框输入名称，创建后选中，并给出一条空线路等待填地址。

## 5. Aether 复用能力边界

放进 Aether（任何宿主可用）：

- `ProvidersSettings`（导出不变）：列表、详情、对话框、提交队列。
- `ModelSelect`（导出不变）。
- 内部组件：`EndpointPanel.svelte`（替代 `EndpointCard`）、`ModelSettingsDialog.svelte`（从折叠区抽出）、`ModelPickerDialog`、`SecretInput`。
- `draft.ts` 纯函数。
- 主题语义色合同（§6）。

留在宿主：密钥查看的权限边界（Web 需当前密码，桌面走本地凭据），已通过 `ProvidersPort.revealNeedsPassword/revealKey` 抽象；角色绑定（`AiSection`）。

AutoNote `AiSection` 中独立的“查看已保存的密钥”区与 `ProvidersSettings` 的密钥行重复，删除；连带删除只为它存在的 `AiHost.revealKey/revealNeedsPassword`、桌面 `ai_endpoint_key_reveal` 命令和 `ai.key_reveal*` 文案。

## 6. 主题：语义色合同

原则：组件只写语义类，具体颜色只在主题层；切换/新增主题只改变量。

- 继续以 shadcn 变量为基础（`background`、`foreground`、`muted-foreground`、`primary`、`destructive`、`border`…）。
- **新增且仅新增**状态色：`success`、`warning`、`info`（`--color-*` 由 `@theme` 暴露为 `bg-success`、`text-info` 等）。
  - `styles.css`（无自有主题的宿主）给出亮/暗默认值。
  - 自有 Tailwind 入口的宿主（AutoNote）在自己的 `@theme` 中映射：`--color-success: var(--success)` 等。
- 撤销上一版临时加的 `control-enabled/disabled/thumb` 和 `chart-*` 当状态色的用法。
- 用法：
  - Switch（全局，含服务商启用开关）：与 AutoNote 设置页原生开关一致，开 = `primary`（宿主强调色），关 = `muted-foreground/35`，白色滑块；不单独改成绿色，保持全应用开关一致。
  - 能力标签：视觉 `success`、推理 `info`、工具 `warning`、联网 `primary`；胶囊为 `bg-*/15 text-*`。
- 宿主映射清单写入 Aether `docs/16 §3`，AutoNote 新增 `--info` 亮/暗值。

## 7. 开发顺序

1. Aether 主题合同：`kit.css` 状态色、Switch 对比度、docs/16 §3。
2. `draft.ts`：`savable` / `adopt` / `nextSlug` + 单元测试。
3. `ProvidersSettings` 重写：列表、标题、提交队列、对话框（新增服务商 / 服务商设置）。
4. `EndpointPanel` + `ModelSettingsDialog`，删除 `EndpointCard` 与 `<details>` 模型设置。
5. i18n：新增/删除键，中英一致。
6. Aether check + 测试；提交推送。
7. AutoNote：更新 pin、`ui.css` 映射、`--info`、删除重复密钥区及死代码；`web:check`、Web 测试。
8. **先部署 Web 本地版**（`vite --force`，避免旧组件缓存）并在真实 Chromium 登录后点击验证；再桌面打包与 WebView2 验证。

## 8. 验收（必须在真实页面操作）

1. 点启用/停用：不出现保存栏；左侧状态点同步；刷新后保持；聊天模型选择器中该服务商模型隐藏/恢复。
2. 改地址后失焦：自动保存；刷新后保持；填 `ftp://` 就地提示且不发请求。
3. 编辑密钥失焦：保存；之后再改地址，请求中不带 `apiKey`；删除密钥后显示“无密钥”。
4. 检测：成功显示可用模型数；错误显示原因（缺密钥、401、404、超时）。
5. 同步模型 → 选择 → 使用：立即保存，模型按组显示；行内设置改上下文窗口后保存，刷新可见。
6. 手动添加、移除模型、移除整组：立即保存。
7. 新增服务商 → 填地址 → 填密钥 → 同步：全程无保存按钮，结果正确；多线路切换互不串数据。
8. 保存失败（断开后端）：toast；本地值保留；切换服务商时提示放弃。
9. 浅色/深色、换强调色：开关关闭态清晰可见，能力标签可辨；320/375/414/768 px 无横向溢出。
10. Web 与桌面执行同一套 1–9。
