# 29 Cherry 风格网络搜索设置设计与实施

> 产品：AutoNote；框架：Aether；参考项目只读：Cherry Studio。
> 数据政策：新系统，不做历史数据导入、密文转换、旧字段兼容或双写。使用新搜索 schema，已有配置重新填写；开发不擅自清空用户数据。
> 状态：本章范围已实现并按第9节验证；供应商联验/线上部署/完整安装生命周期边界明确保留。

## 1. 范围与归属

本轮完整交付：常显 Key 输入、紧邻获取密钥/检测、检测前保存、多 Key 管理、结果数、none/cutoff 压缩、黑名单、模型原生 Web 工具优先、Web/桌面实际接入。

Aether 拥有 SearchPort、共享 Svelte UI、本地 search.db、Rust 搜索与模型协议；AutoNote 拥有 Worker/D1/HTTP适配、笔记宿主与发布依赖。Cherry源码不修改，不复制其 React/Electron/路由。

参考：Cherry `WebSearchProviderSetting.tsx`、`WebSearchApiKeyList.tsx`、`WebSearchGeneralSettings.tsx`、`SettingsPrimitives.tsx`。继承布局和草稿行为，不复制框架。

## 2. 交互

- 每项能力一组：标题、当前服务商描述、右侧选择器；描述不重复。
- Key 密码框始终可见；获取密钥在标题旁；添加/检测按钮紧邻输入框。已有凭据只以掩码列表显示，不填充为输入值。
- 多 Key 列表：新增、修改、删除、显式复制；列表接口不返回明文。Web显式读取/复制已有 Key 必须验证当前密码，离开面板清除已显示明文。
- 空白输入不删除旧 Key；删除为明确操作；新增/修改失败保留草稿。
- 检测先保存地址/用户名及新Key草稿；失败不检测；运行期间相关操作禁用。
- 高级设置默认折叠：结果数、压缩、黑名单。模型工具优先是全局搜索政策，单独一行，写作不使用。
- AutoNote设置外层已有滚动容器，保持单一滚动所有者；卡片不设固定高度。不凭截图判断滚动是否失效。
- 本轮不做Zhipu特殊继承：AutoNote模型服务可配置任意兼容线路，没有Cherry的固定Zhipu身份；Zhipu仍允许在搜索设置直接填Key，避免跳转按钮无实际凭据来源。

## 3. 冻结端口（camelCase）

```ts
type SearchKey = { id: string; masked: string }
type SearchPreferences = {
  maxResults: number // 1–50，默认5
  compression: 'none' | 'cutoff' // 默认none
  cutoffLimit: number // 100–20000字符，默认2000
  blacklist: string[] // 最多32项，每项256字符
  modelToolsPreferred: boolean // 默认false
}
// SearchProvider删除apiKeyMasked，增加keys: SearchKey[]。
// SearchSettingsDto保留capability/defaultProvider/providers，增加preferences。
// SearchSave仅capability/provider/baseUrl?/basicAuthUsername?，不再携带旧apiKey。
settings(capability): Promise<SearchSettingsDto>
save(input: SearchSave): Promise<SearchSettingsDto>
setDefault(capability, provider): Promise<SearchSettingsDto>
savePreferences(input: SearchPreferences): Promise<SearchPreferences>
saveKey(capability, provider, value, keyId?): Promise<SearchSettingsDto>
removeKey(capability, provider, keyId): Promise<SearchSettingsDto>
reveal(capability, provider, keyId, currentPassword?): Promise<string>
check(capability, provider): Promise<{count:number}>
search(query): Promise<SearchResult>
fetch(url): Promise<SearchPage>
```

所有接口沿用CallOptions取消。Key最多16项，每项4096 UTF-16 code units（复用现有凭据vault上限）；去掉首尾空白，拒绝空值，不回显非法输入。更新/删除/读取必须匹配capability/provider/keyId及Web userId。普通返回只有掩码。

HTTP：GET search/settings；PUT search/providers/default/preferences；PUT search/keys（capability/provider/value/keyId?）；DELETE search/keys/:id（capability/provider）；POST search/reveal（含keyId、currentPassword）；现有query/fetch/check不变。

Tauri新增search_save_preferences/search_save_key/search_remove_key，更新search_reveal，使用既有aether:search权限。所有消费者直接迁到新合同，不留旧参数shim。

## 4. 最终存储

本地search.db：search_settings(capability,provider)；search_providers(capability,provider,base_url,basic_username)；search_keys(id,capability,provider,key_ciphertext,position)；search_preferences单行JSON。

D1等价表全部以user_id隔离。沿用既有加密函数及密钥绑定ID；不新建加密算法。凭据逐条加密；没有enabled/lastUsedAt/遥测等无需求字段。schema创建使用现有初始化入口，不读取旧单Key列；不自动删除旧数据库。

## 5. 执行语义

- 每次执行从下一个Key开始轮换，顺序稳定；内存计数不持久化。可选Key provider无Key仍按既有匿名请求。
- 仅明确HTTP401/403/429尝试本次尚未用过的下一个Key；最多Key数量次。网络异常/超时/取消/5xx不轮换。不跨provider，不开启无限重试。搜索和fetch两项都执行该政策；检测也走相同执行器。
- 结果先解析/去重，后黑名单过滤、再cutoff；返回UI与注入模型使用同一处理结果。none不额外截断；现有2MiB响应、上下文安全预算仍有效。
- 黑名单支持hostname（example.com及其子域）、hostname通配（*.example.com）、完整HTTP(S)URL通配（*://*.example.com/*）；大小写按host规范化，path区分大小写。使用简单线性通配匹配；本轮不引入用户正则，避免Web ReDoS。非法规则整次保存拒绝，不静默忽略。
- cutoff按Unicode字符截断snippet，保留title/url，不在UTF-16 surrogate中间截断；独立网页读取同样拒绝黑名单目标及重定向目标，cutoff作用于page.content。

## 6. 模型原生Web工具

模型配置显式增加nativeWebSearch: boolean（默认false；只接受Anthropic Messages/OpenAI Responses，OpenAI Chat不支持）。能力必须由用户声明，未知兼容模型不根据名字猜测。

用户联网开关关闭：不执行外部/原生搜索。开启且preferences.modelToolsPreferred=true且模型声明能力：发送供应商原生工具（Responses web_search；Anthropic web_search_20250305），不执行外部预搜索；否则沿用外部搜索。协议解析保留供应商可见正文与引用，原生工具不进入本地host ToolExecutor。配置不支持时回落是确定路由，不因上游失败静默换服务。

原生搜索会由供应商处理当前模型请求，可能包含对话及附带笔记上下文；UI提示与外部仅发送本轮问题的提示必须区分。黑名单/截断作用于本地外部结果；不能冒充控制供应商原生检索。开关旁说明该边界。

协议依据：[OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)、[Anthropic Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)。使用基础Messages工具版本而非引入动态代码过滤；服务端可在一次请求中多次搜索，不新增本地自主多轮编排。
