## 1. 结论

- 桌面宿主 `desktop/src` 只做三件事：装配组合根、实现 `IpcBackend`、提供桌面专属设置分区。所有业务界面都在 `packages/app` 里，由 `mountApp(target, deps)`（S7-1）挂进 SvelteKit 的唯一页面。
- 整个前端只有 `desktop/src/lib/ipc/transport.ts` import `@tauri-apps/api/*`，它导出 IpcTransport 的 Tauri 实现。端口适配器通过构造参数获得 transport，按 20 §6 映射 command；files.resolveUrl 是纯同步转换，File 上传是分块会话，不硬套一方法一 command。AppError 仅在 transport 边界转 BackendError。文件选取用根包官方 dialog 的 Rust API，不暴露 JS 任意路径读写权限。
- `autonote://library-changed` 由 transport 订阅，载荷为本地 `SyncResponse`，转成 `ChangeEvent{kind:'library',payload}` 交给 `IpcChangeFeed`，包含 notes、folders、tags、deletions 和本地 cursor。附件的 URL 在 `files.resolveUrl` 里改写：`/api/files/<id>` 改成 `convertFileSrc(id, 'autonote-file')`，Windows 上的结果是 `http://autonote-file.localhost/<id>`。笔记正文不做任何改动。
- 账号、分享、远程备份、更新检查这几类界面，完全靠 `capabilities` 加可选端口「不提供」来隐藏，宿主代码里不写 `kind === 'desktop'` 的分支。MCP 和同步的能力开关由 D4/D5 在组合根里打开。
- 导入导出（D3）全部在 Rust 的 `note-core/src/transfer/` 完成。ZIP 用 `autonote-markdown-backup` v3、JSON 用 `autonote-export` v1，与 Web **语义和文件哈希互通，不要求 ZIP 压缩字节相同**。导入支持 v2/v3 备份 ZIP、JSON bundle、散装 Markdown 和 Obsidian vault ZIP/目录。进度只走调用级 `tauri::ipc::Channel<ProgressEvent>`，取消使用 jobId；§5 定义完整校验和原子可见恢复。
- 系统集成（D6）用官方 single-instance、global-shortcut 插件与 Tauri 自带 tray-icon。窗口状态由 `shell::window_state` 保存到 `data\window-state.json`，WebView2 数据到 `data\webview\`，均以真实 exe 所在目录为根。NSIS 选择 currentUser 安装模式，但写权限、升级和卸载保留数据必须用实际安装包验证，不由配置字段直接推定。

## 4. D2 宿主与界面接入

### 4.1 端口与组合根

`bootDesktop(target)` 顺序为创建 transport/logger → 建立并等待变更监听 → `session.load()` 与 `notes.snapshot()` → 构造共享状态及平台接缝 → `mountApp`。任何一步失败都逆序释放已创建资源，页面展示可重试的启动错误而不是空白窗。共享状态只通过 Backend 与 Logger 访问宿主。

`IpcBackend` 实现 10 §2 的完整必选端口：notes、folders、tags、search、files、settings、transfer、session、changes；方法名严格复用 10，不能把 remove 改成 delete、把 importFrom 改成 import。notes 包括 snapshot/list/get/create/patch/remove/restore/purge/duplicate/emptyTrash/versions/version/restoreVersion/backlinks/flush；search 包括 query/graph/reindex；files 包括 list/upload/remove/prune/resolveUrl。桌面不提供 notes.syncNow，D5 的远程同步由宿主扩展调用；不另造公开 sync 端口。D4 接入可选 mcp 及 local 扩展，按 22 显示。

`notes.patch` 在 SQLite 提交后返回 `{queued:false,writeId,note}`，writeId 原样关联 app 本次输入，不建立桌面 outbox，不返回 queued:true。GUI rev 冲突保留编辑缓冲；transport 不自动 rebase。`notes.flush(noteId?)` 等待此前已接收的本地写入，返回 `FlushResult{pending,failed}`，正常耐久提交为两者 0；失败计数或未完成数非零不能确认关闭，不等待远程同步。

capabilities 固定 accounts/totp/share/remoteBackup/semanticSearch/updateCheck=false；本地 ChangeFeed 就绪时 realtime=true；D4 服务可配置时 mcp='local'；D5 接入后 remoteSync=true。能力是已实现能力，不是「此刻网络可达」；不因服务临时停机把设置入口藏掉。session 返回稳定本地 library 身份，使用 10 的 BackendSession，其中 `site.attachmentStorage='local'`；不得扩写 HTTP SiteInfo 枚举。session.logout 调用返回 forbidden，不删本地库或凭据，桌面不呈现登出按钮。

返回封套不泛化：notes.list→ListNotesResponse，snapshot→完整 SyncResponse；create/remove/restore/duplicate/restoreVersion→Note；purge→`{ok:true,cursor}`；emptyTrash→`{purged}`；versions→NoteVersionMeta[]、version→NoteVersion、backlinks→Backlink[]；files.list→AttachmentPage，search.graph→GraphResponse 且保留 meta 截断信息。restoreVersion 端口不加 rev 字段，适配器在本地读当前 rev 后调用 core CAS，期间变化返回 conflict，不覆盖新版本。其他方法精确采用 10 §2，而不是统一 `{ok:true}` 或任意数组。

### 4.2 Transport 与运行时接缝

`IpcTransport` 在 transport.ts 定义类型与实现，提供类型化 invoke、listen、文件对话框、附件 URL 转换、窗口关闭协调和调用级 job 封装；调用方拿到普通 Promise、卸载函数与端口进度回调，不拿 Channel 对象。errors.ts 校验 `{code,message,details?}`，按 02/10 映射 status；取消用 cancelled，超时用 request_timeout，成功响应形状非法用 invalid_response，其他未知故障用安全 internal。这三种新增 code 仅客户端使用，不改 Worker HTTP 错误集合，不透传 SQL/路径/原始栈。

宿主接缝的必要签名如下；`CommandArgs/CommandResults` 是按 20 §6、22 及本章宿主 command 建立的**具体映射**，不可用 Record<string,unknown> 擦除领域输入输出。TransferOptions、ProgressEvent、FlushResult 直接从 app 端口引入：

```ts
interface IpcTransport {
  invoke<K extends keyof CommandArgs>(
    command: K,
    args: CommandArgs[K],
    options?: CallOptions,
  ): Promise<CommandResults[K]>
  listenLibrary(listener: (payload: SyncResponse) => void): Promise<() => void>
  changesSince(since: number): Promise<SyncResponse>
  resolveFileUrl(id: string): string
  uploadChunk(
    uploadId: string,
    offset: number,
    bytes: ArrayBuffer,
    options?: CallOptions,
  ): Promise<{ received: number }>
  exportTo(format: 'zip' | 'json', options?: TransferOptions): Promise<{ saved: true } | null>
  importFrom(
    source: 'files' | 'folder',
    conflict: 'skip' | 'newer' | 'duplicate',
    options?: TransferOptions,
  ): Promise<ImportResult | null>
  onPrepareClose(flush: () => Promise<FlushResult>): Promise<() => void>
  dispose(): Promise<void>
}
```

exportTo/importFrom 是 transport 的调用级 Channel/取消封装，IpcTransferPort 公开 readonly sources 并调用它们；所有真实参数解析、文件选择在 Rust。changesSince 只由 ChangeFeed 使用，不增加 Backend 公共方法。uploadChunk 的 received 是当前会话已接收累计字节，错 offset 报错而非猜测重传。

页面仅 onMount 启动；若异步 boot 在页面卸载后才完成，立即销毁 handle。`Backend.dispose()` 幂等：取消尚可取消的 job、等待已提交操作收尾、unlisten、解除 close 协调、断开状态订阅、刷新日志；销毁不删除数据，也不强杀 Rust 提交。JS 监听注册晚到也必须执行 unlisten，避免热重载双通知。

`PrefsStore` 的界面偏好继续走 WebView localStorage；领域 `UserSettings` 经 settings.get/save 落 SQLite；托盘/快捷键/退出行为经桌面专属设置 command 落 `desktop-prefs.json`，三者不混用。用 `WebviewWindowBuilder` 明确设置 `data_directory(data/webview)` 后创建唯一 main 窗，配置窗设 `create:false` 防止默认窗先使用系统缓存目录。CSP 仅放实际用到的资源源；正常导航、外链 opener、导入目录各自鉴权，不能以便携需求开放全盘 FS。

### 4.3 事件、快照与状态合并

唯一领域通知是 `autonote://library-changed`，payload 严格是本地 `SyncResponse`，适配为 `library`；禁止旧 notes-changed、kind:notes 和全局 progress 事件。提交后释放 DB 锁再发送，只有摘要，不广播正文。无论 GUI、MCP、导入或远端 pull 写入，都从同一 Library commit 边界通知。

先订阅并缓存通知，再读取 snapshot(cursor=C)，安装快照后按 cursor 顺序应用 C 以后的通知。较旧/重复 cursor 忽略；笔记按本地 rev 合并；folders/tags 以响应的完整集合与 cursor 更新，deletions 建墓碑。缺口、通知失败、窗口恢复前台或 WebView 重载时，transport 内部经 `library_changes({since})→SyncResponse` 补拉到 hasMore=false；过期 since 由该命令返回 full=true 的完整快照，按 snapshot 语义安装。notes.list 是 ListNotesResponse 列表分页，不能借作增量流。新窗口不得只依赖内存通知；补拉期间继续缓冲，完成后再消费更高 cursor，避免正文版本/组织集合漏变更。全量安装仍保留脏编辑缓冲，不能用远端 rev 比较或覆盖。

同步服务的远端 cursor 不进入该载荷；note-sync 先提交本地变更，才由 core 发本地 cursor。settings 保存/外部更改适配 `settings`，连接状态适配 `connectivity`；不新增 watchWrites 总线。桌面无 queued 写入，通常不产生 write 事件。

### 4.4 附件 URL 与安全边界

`files.resolveUrl` 只识别合法相对 `/api/files/<26位id>`，验证完整 pathname，不把查询参数、任意 URL 或用户文本拼入磁盘路径；HTTPS 外链维持原值并受渲染安全策略控制。正文存储和导出仍保留逻辑 URL，不能持久化 `http://autonote-file.localhost`、绝对 data 路径或 blob URL。

protocol handler 属于 D1-7：只按 ID 查已提交附件元数据和受限文件路径，拒绝非法 ID、编码斜线、目录访问、已删除/未发布文件；不暴露 stage。设置响应 MIME、安全 headers 与实际媒体需要的 Range 行为。Windows 的 CSP 对 img/media 等实际消费源放行 `http://autonote-file.localhost`；其他支持目标按 convertFileSrc 的实际源验证，不仅写 `autonote-file:` 就声称 Windows 可用。

`files.upload(File,noteId?,options?)` 必须覆盖编辑器粘贴产生的内存 File，不能只支持系统文件路径。transport 使用 `files_upload_begin({filename,mime,size,noteId?})→{uploadId}`、files_upload_chunk、`files_upload_finish({uploadId})→Attachment`、files_upload_cancel。uploadId 为随机不可猜的短期句柄，绑定发起窗口，会话空闲 5 分钟或窗口销毁即取消回收，finish 后不可复用。begin 校验 LIMITS/配额；File.slice 分 256KiB 读取，chunk 用 Tauri 原始二进制 Request body，uploadId/offset 放受校验请求元信息，逐块 await 提供背压，不用 JSON 数字数组或 base64 整文件。后端检查 offset 连续、实际累计长度、MIME/hash、同窗口所有权，finish 才通过 D1 stage 发布和 DB 提交；取消/超时/断窗移交引用保护清理。错序/超长/超限失败不创建可见附件，成功返回实际 Attachment。resolveUrl 是同步纯前端转换，无 IPC command。

### 4.7 生命周期与保存确认

### 4.8 端口行为验收方式

## 5. D3 导入导出

### 5.1 格式与互通边界

格式权威是 `packages/shared/src/backup-format.ts`（迁自已核对的 参考项目 同名文件）及迁入 Web worker 的 `backup/snapshot.ts`、`routes/transfer.ts`、`lib/obsidian-import.ts`。Rust 实现同一格式，不能凭名称另造字段。完整备份输出 v3；v2 只读。JSON 输出 `autonote-export` v1，字段复用 ExportBundle，含 user/folders/tags/notes；当前 Web JSON 导出 attachments=[]，因此 JSON 不宣称包含二进制附件、历史版本、凭据或宿主偏好，UI 明示完整附件请用 ZIP。读取旧 JSON bundle 内附件时按其实际编码/归档路径校验，不猜新格式。

v3 根为 `manifest.json`、`COMPLETE`、`notes/`、`archived/`、`trash/`、`attachments/<sha256>--<filename>`。manifest 保留 format/version/appVersion/createdAt/snapshot/notes/attachments；每条 note 的 id/path/title/folder/attachmentHashes/state/archived/bytes/sha256/createdAt/updatedAt/deletedAt 与 shared 一致。v2 的 manifest、COMPLETE 和笔记放在 `snapshots/<stamp>/`，附件仍走格式规定的共享路径。识别单一根前缀；多个完整快照按 Web 选择规则取最新完整者并给 warning，歧义/同时间冲突拒绝，不凭 ZIP 顺序选择。

COMPLETE 精确采用 `autonote-markdown-backup vN\nmanifest-sha256 <hex>\n`，校验实际 manifest 原始字节的 SHA-256；每个 payload 校验其长度与 SHA-256。正文/frontmatter/附件逻辑链接的构造和解析沿用 Web 语义。ZIP 顺序、压缩级别、容器时间戳、JSON 空白不属于跨实现一致性；验收比较解包校验结果和导入后领域语义，不比较整个 ZIP 的 SHA-256。

### 5.2 Core 模块与快照导出

`core/src/transfer/{mod,format,export,import,obsidian}.rs` 分别承载服务入口、格式验证、导出、恢复计划和 Obsidian 解析；复用 D1 的 Library、附件 stage 与纯派生函数，不绕过写入管线。服务 export_to/import_from 接收受限输入/输出句柄、格式/冲突选项、ProgressSink、取消令牌；core 内部可保留计数，适配到公共 exportTo 的 `{saved:true}|null` 和 importFrom 的 `ImportResult|null`，不发明共享 ExportResult。

core 服务签名固定为下列同步接口，由 command 放入 spawn_blocking；以下为设计契约，不是未实现产品代码：

```rust
impl TransferService {
    pub fn export_to(&self, output: AuthorizedOutput, format: ExportFormat,
        progress: &dyn ProgressSink, cancel: &CancellationToken)
        -> Result<TransferOutcome<ExportSummary>, Error>;
    pub fn import_from(&self, input: AuthorizedInput, conflict: ImportConflict,
        progress: &dyn ProgressSink, cancel: &CancellationToken)
        -> Result<TransferOutcome<ImportResult>, Error>;
}
pub trait ProgressSink {
    fn report(&self, event: &ProgressEvent);
}
pub enum TransferOutcome<T> { Completed(T), Cancelled }
```

ExportFormat=Zip/Json、ImportConflict=Skip/Newer/Duplicate。AuthorizedInput 是已打开文件集合或受限目录根，不提供从前端字符串直接构造的入口；AuthorizedOutput 持有用户确认的目标目录句柄/文件名及覆盖授权。ExportSummary 仅含 format/noteCount/attachmentCount/bytes，映射公开 `{saved:true}`。CancellationToken 由 job registry 持有，内部原子取消标记与提交状态门不依赖 Tauri。ImportPlan 在 stage 的独立 SQLite 数据库保存（与活库分离），只在全量验证后允许进入写栅栏。

导出步骤：

1. 获取一致 SQLite 读快照，枚举 notes/folders/tags/附件引用并 pin 所需附件对象，防止清理线程删除；导出不包含同步映射、MCP token 或桌面偏好。
2. 从同一快照分批读取正文，按 Web 转换生成 Markdown/frontmatter，流式写 ZIP 与 SHA-256，不把全库/二进制拼成大 JSON IPC。JSON 受 bundle 限制且只提供格式支持的数据。
3. 输出放在目标文件同目录的随机 `.partial`，先写 payload，再写 manifest/COMPLETE，flush/sync 后关闭句柄。各文件与领域字段必须符合单项 LIMITS；JSON 遵守 bundle 上限。ZIP 导出允许全库备份，不套 HTTP 上传总量阈值：大 ZIP 提示先解压后选备份文件夹流式恢复，小 ZIP 可直接导入；两种路径都必须实际验收，不输出无恢复路径的「成功备份」。
4. 在最终发布前检查取消；未提交则删除 partial 并释放 pin。进入发布临界区后不再取消，以安全同卷替换/rename 发布目标；替换失败保留旧目标，报错误。目标覆盖必须先由保存对话框确认，不先截断旧文件。
5. 成功端口结果为 `{saved:true}`；格式/计数留在 job 内部日志摘要，选定显示文件名由宿主已有选择状态展示，实际路径不进入共享领域实体或普通日志。无论成功/失败均释放快照、pin 与临时文件。

### 5.3 校验、安全与导入计划

所有输入先验证后写库，默认 conflict=skip；可选 newer/duplicate，语义对齐 Web：相同 ID 的 newer 仅在 imported.updatedAt 严格更大时替换，相等跳过；duplicate 分配新 ID 并重写本批内部链接；修改已有笔记保留旧版本。导入 rev 不能直接成为本地 CAS rev，创建/更新由 Library 分配本地 rev/cursor。文件夹按层级/名称映射，标签按规范化名称处理，attachmentHashes 映射到本地 ID；不以文件名判断附件相同。恢复是原子批量合并，不隐式清空库，也不把备份里的删除状态扩展到库内未包含的笔记。

验证顺序与失败行为：

- 打开用户选定句柄并区分**普通 files 上传/ZIP**与**folder 流式恢复**。普通路径沿用 shared LIMITS：文件数 500、输入 64MiB、JSON 32MiB、ZIP 条目 2500、展开总量 80MiB、单附件 25MiB；以迁入常量为唯一来源，ZIP 对目录声明和实际展开流双重计数，压缩比不替代真实字节。大 ZIP 明示解压后选 folder，不静默截断。
- 备份目录（包括大型备份解压目录）不套 HTTP 单请求 500 文件/64MiB 输入/80MiB 展开总限，也不人为限制整库大小。按文件流式读取，单 note 正文/字段、单附件仍遵守领域 LIMITS；manifest 流式解析/hash、唯一性与引用闭包在磁盘暂存 SQLite 中验证。全局可恢复前提为磁盘可用空间、SQLite 能力和本地有效配额；先估算 stage+活库/WAL 增长空间，过程中继续处理磁盘满，不把内存读入整目录。Obsidian folder 同样流式建立磁盘索引，不套 ZIP bomb 的展开总限。
- 只支持受实现验证的 ZIP 存储/deflate；拒绝加密、损坏/截断、重复条目、伪造大小、CRC 错误、符号链接/硬链接等特殊条目。任何备份控制标识存在时严格按备份校验；manifest/COMPLETE 坏了不得降级为普通 Markdown 导入。
- 路径按 `/` 分段验证，拒绝绝对路径、UNC、盘符、反斜线、空段、`.`/`..`、NUL/控制字符、Windows ADS 冒号、保留设备名与结尾点/空格；大小写折叠后重复条目拒绝。路径作为归档逻辑键，不直接拼入文件系统；stage 使用宿主生成 ID 文件名。也不二次 URL decode 后再写磁盘。
- Vault 目录枚举和打开时拒绝 symlink/junction/reparse point，句柄解析目标必须仍在选定根内；不能只做字符串 startsWith，也不能先检查后无保护地跟随链接。拒绝访问中被替换为外部路径的文件。
- 校验完整 manifest 结构、版本、唯一 ID/hash、毫秒时间、folder 深度、state/deletedAt 一致性、附件引用闭包；校验每个声明文件的长度和 SHA-256、Markdown 严格 UTF-8。未知版本或缺失引用整体失败，附安全字段路径，不打印正文/绝对路径。
- 解析全部 JSON/Markdown/frontmatter，检查字段 LIMITS，形成只含已验证变更的 ImportPlan；非法数据、权限不足、磁盘满一律不写部分笔记。unsupported Obsidian 元信息可在明确的 warning 中保留原文，但不是忽略损坏 payload 的借口。

目录恢复保留大型备份能力：stage 的独立 SQLite 保存 manifest 索引、导入计划、冲突映射和附件引用，正文/附件顺序落盘；内存只保留固定读取窗口及当前记录。预检/校验阶段可分批提交**暂存计划库**，不会改变用户库；全部验证完成后，对活库的全部领域变更仍用单事务完成原子可见切换，事务中逐页读取计划，不再把大库实体装入 Vec。若空间不足或取消，回滚活库并保留旧状态，不把先前分批预检误称已经恢复成功。Web 对大备份文件夹仍使用其原有分批上传语义，桌面的磁盘暂存是适配，不修改 Worker API。

### 5.4 附件 stage 与原子可见恢复

SQLite 与文件系统不是同一事务；本设计承诺**读者看到完整旧状态或完整新状态**，不承诺它们能做跨资源原子 rename。恢复不用替换正在使用的 library.db，也不触碰 WebView 缓存、同步凭据和 MCP 设置。

1. 创建 `data/staging/import/<jobId>/`，以生成的临时对象名流式存储附件和计划库，写 job journal（对象 ID/hash/目标/阶段，不含正文和 token）；全量验证通过并 flush/sync 后标记 validated。大型目录通过分页读取暂存计划，不受单次 HTTP 总量阈值约束，尚不修改活库。
2. 获取 Library 写入栅栏，暂停新的 GUI/MCP/pull 提交与附件清理，导出已有 pin 仍受保护。重读冲突目标及配额，基于此刻数据重算 skip/newer/duplicate，不能把预检后的外部编辑静默覆盖。
3. 检查取消并进入 publishing。相同哈希复用已验证对象，缺失附件以全新对象 ID 在同卷 stage→files rename，禁止覆盖旧引用对象。所有目标文件可读且 hash 正确后才能引用；发布失败留旧 DB 不动，并将孤儿交给恢复清理。
4. 在**一个 SQLite 事务**内经 core 写入附件元数据、笔记/文件夹/标签、版本、派生链接/FTS、changes 和导入提交标记；导入写入走 `WriteOrigin::Import`，按 22 §6.2 登记脏标记，不复制备份中的同步绑定、`sync_item` 或远端游标。失败 rollback，全库对读者仍是旧状态。
5. 提交前最后检查取消；COMMIT 与取消由同一状态门裁决，一旦进入 committing 则不可取消，UI 显示「正在完成」，最终返回成功/真实失败而非虚假的 null。成功记录 committed 标记、释放锁并发一个合并的 library-changed 通知；结果计数与实际事务一致。
6. 提交后清理 journal/stage。取消/失败只删本 job 的 staging 和确认未被 DB、其他 job、导出 pin 引用的对象，不按文件名批量删 files。进程崩溃重启时先读 DB 提交标记：已提交则保留引用文件并完成收尾；未提交则按引用检查回收新孤儿。恢复完成前不启动附件 prune。journal 丢失时也以数据库引用/pin 为准，不把未知文件冒充已提交附件。

崩溃点验收必须覆盖 stage 完成、第一次 rename 后、DB 提交前、提交后清理前。重启后的笔记数量/版本/附件 hash 必须属于完整旧库或完整新库；不能出现已提交正文指向缺失附件。断电级持久性遵守 SQLite 与文件系统能力，Windows 锁文件/同步失败按失败返回，不声称任意文件系统都可恢复。

### 5.5 Obsidian 与散装 Markdown

Obsidian ZIP/目录走同一 ImportPlan 和原子提交；不执行 `.obsidian` 插件、配置、脚本，不联网抓附件。两遍解析：第一遍建立 vault 相对路径/标题索引及附件索引、为笔记分配 ID；第二遍解析 frontmatter、`[[笔记#标题|别名]]`、`![[附件]]` 与相对 Markdown 链接，使用 Web `obsidian-import` 的优先级（相对路径优先、唯一名称匹配），重写为本地逻辑链接。重名歧义不任意选择，保留原链接并返回 warning；片段/别名保留，代码块/行内代码和外部 URL 不误改。

folder 层级映射受深度限制，标题、tags、时间字段和 Obsidian 注释处理按 Web 现有规则；无法表达的 frontmatter 保留，不假定其全部是产品字段。资源按实际内容/MIME 白名单验证后 stage；同 hash 去重。散装 md/markdown/txt 使用同一严格 UTF-8 与正文限额，不因扩展名 `.txt` 绕过限制。ImportResult.warnings 最多 100 条，超额在最后一条汇总省略数量，不新增未定义 DTO 字段或把源路径刷进日志。

### 5.6 IPC、Channel、取消与界面

app 只使用 transfer.sources/exportTo/importFrom；sources 是 readonly `('files'|'folder')[]` 属性，exportTo 返回 `{saved:true}|null`，importFrom 返回 ImportResult|null。Root command 为 transfer_export、transfer_import、transfer_cancel：开始 command 仅接收 format/source/conflict、jobId、`Channel<ProgressEvent>`，不接受任意 path。transfer command 在根包用官方 dialog Rust API 打开原生选择器（不阻塞 UI 线程），立即把选择解析为受限文件句柄/目录根再传 core；路径不回传共享 app，也不用 JS 声明「已授权」的任意字符串。取消选择返回取消标签→null，不启动 core 作业、不 toast；对话框期间 jobId 仅保留取消意图，AbortSignal 到达则选择完成后也不得启动作业。已选文件的真实打开/遍历仍按 §5.3 防路径替换。transport 只封装命令与 Channel，无需 JS dialog 插件或全盘 FS 权限。

`ProgressEvent` 严格复用 10：`{jobId,phase,completed,total,terminal:boolean}`，phase 为 validating/reading/writing/uploading/finalizing。内部状态 preparing/staging/publishing/committing/cleanup 不冒充公共枚举：预检映射 validating，快照/输入读取映射 reading，stage/压缩/对象发布映射 writing，提交与清理映射 finalizing；本地传输不产生 uploading。阶段 completed 单调递增，未知 total=null，否则 completed≤total；阶段内部统一单位，不能把 bytes/条数相加。每 job 结束最多发一个 terminal=true，成功/取消/失败由 command 的真实终态结果区分，不塞入 terminal 字符串。根包限频约 10Hz，终态不节流丢弃。Channel 仅路由本次调用，jobId 防止过期 UI 更新。

AbortSignal 触发 transfer_cancel(jobId) 设置线程安全令牌，不是丢弃 Promise。注册与 cancel 竞争时保留本连接已授权 job 的预取消状态，启动立即检查；重复 cancel 幂等。cancel 返回是否接受，进入 committing/已完成则未接受，原 Promise 返回真实终态。core 在解压 chunk、文件间、事务提交前检查取消并 rollback；成功用户取消后 transfer 端口 resolve null，这是该端口明确的 null 合同。其他端口取消转换 BackendError(cancelled)，超时 request_timeout，响应非法 invalid_response，不以 internal/details.cancelled 混淆。原始 IPC 可返回完成/取消标签，由 adapter 转公共结果；真实失败 reject BackendError。

窗口销毁/Channel 接收端消失时，根包取消仍可取消阶段，已进入提交则完成事务并保留结果；以 command 结果为完成事实来源，不依赖最后一个进度消息一定到达。UI 操作期间锁定重复按钮，取消中显示等待清理，提交期间禁用取消；关闭对话框不暗中放任后台导入。D6 退出协调复用 job registry 等待终态。

## 6. D6 打包与系统集成

### 6.1 单实例与托盘

single-instance 在创建服务/窗口前初始化，第二进程只通知首实例显示、取消最小化并聚焦 main，然后退出；不再次打开 SQLite/MCP 端口，不从命令行执行任意文件导入。桌面发布定义为同应用用户会话一个实例；不承诺同时运行多份 portable 库，验收前关闭其他实例防止误测首进程。

`tray.rs` 创建打开/新建笔记/退出菜单；新建通过宿主 UI 意图通道交给共享命令，不绕过领域端口；左键显示主窗。该 UI 意图不是数据变更事件。托盘不可用则 closeToTray 自动禁用且明确提示，禁止关闭窗口后无入口。所有菜单和 tooltip 用当前语言；托盘退出与窗口退出走相同保存协议。

### 6.2 全局快捷键

`shortcut.rs` 在 Rust 使用官方 global-shortcut 插件，只监听 Pressed，默认 Ctrl+Alt+N 唤出并新建。更改时先尝试注册新组合，成功并持久化后注销旧组合；新注册/设置写入失败保留旧组合，返回可翻译错误。重复组合/被系统占用不假装保存成功。关闭该功能先注销再持久化，进程退出统一释放，最小 capability 不开放前端任意注册快捷键。

### 6.3 关闭、隐藏与真实退出

`desktop_prefs_get/save` 管理 `{closeToTray,globalShortcutEnabled,globalShortcut}`，默认 closeToTray=false，防止用户误以为程序退出。窗口 X 若配置隐藏，也要先 flush 本地编辑；失败保持窗口可见。只有明确退出才停止服务，隐藏后 MCP/同步继续运行。

真正退出由根包 ShutdownCoordinator 串行执行：

1. 拦截 CloseRequested/ExitRequested/托盘退出，设置 closing 标记；同时间多次请求合并。发送主窗 prepare-close 请求并阻止新输入；调用共享 AppHandle.flush() 将编辑缓冲、防抖标题和设置交给端口并等待 notes.flush，仅 FlushResult.pending=0 且 failed=0 时确认给 Rust，非零视为未保存。
2. 若前端报冲突/磁盘失败，保持窗和缓冲，解除 closing，显示具体恢复动作；不自动 force exit。前端失联/超时只提示「无法确认保存」并允许用户取消退出或**明确丢弃未确认编辑后退出**，不把超时当成功。
3. Rust 禁止接收新的 GUI/MCP 写请求，停止同步调度，取消可取消的导入/导出，等待不可取消提交和已接收 Library 写入完成。该写栅栏在禁止新写后等待，因此不存在刚等空又插入的新任务。拒绝请求返回结构化错误，不静默丢失。
4. 保存正常窗口状态、刷新日志并关闭 Library/服务/托盘/快捷键；只等本地耐久提交，不等远端 upload/WS，也不要求此时在线。后台同步未确认记录保留供下次启动继续。
5. 设置 allowExit 后退出，避免 ExitRequested 递归拦截。flush 失败不进入此步；强制终止/系统断电无法保证尚在 WebView 内的输入，这一点不能由窗口状态插件弥补。

### 6.4 窗口状态与便携缓存

`shell::window_state` 存版本、正常态位置/大小、DPI/monitor 参考与 maximized；不持久化 minimized/hidden/fullscreen 作为下次启动不可见状态。以正常态尺寸为准，调整事件防抖 500ms，退出前再写一次，采用同目录 tmp+安全替换，不先截断旧 JSON。损坏文件使用 1280×820，最小 960×640；显示器移除、DPI 改变或位置在屏外时夹到当前工作区，且窗口标题栏可见。小于最小尺寸的屏幕按可用工作区处理，不制造不可操作窗口。

本设计明确不用 window-state 插件，因为必须精确控制保存位置、关闭握手和状态恢复；不是宣称插件不能配置路径。WebView2 必须在创建前指定 data/webview；移动 portable 整个目录后验证库、主题、界面偏好及窗口状态随行，原目录及 APPDATA 不得成为静默新写入位置。DPAPI 凭据跨机器是否可解密按 22 处理，不承诺复制目录就迁移机器绑定凭据。

## 7. 日志事件

统一写入 `data/logs/autonote.log`，按实际写入大小到 5MiB 轮转，最多保留 3 个文件（当前文件+两份历史），长时间运行中也轮转，不仅在启动时检查。writer 内部串行轮转，Windows 文件句柄先关闭再 rename，初始化/轮转失败不递归记日志或 panic；诊断区显示日志不可用，但 Library 保存失败仍必须阻止保存成功提示。日志不能放进备份/portable ZIP。

| app.window.restore_adjusted                           | warn         | reason、dpi                                           | window                   |
| app.shutdown.completed / app.shutdown.failed          | info / error | durationMs、pendingCount、code                        | ShutdownCoordinator      |
| app.shortcut.registration_failed                      | warn         | code                                                  | 设置 command             |
| transfer.export.completed / transfer.import.completed | info         | jobId、format、noteCount、attachmentCount、durationMs | 根包 job 终态            |
| transfer.job.cancelled                                | info         | jobId、phase                                          | 根包 job 终态            |
| transfer.job.failed                                   | error        | jobId、phase、code                                    | command 边界             |
| transfer.recovery.completed                           | info         | recoveredCount、orphanCount、durationMs               | 启动恢复                 |
| ipc.change.reconciled                                 | debug        | cursor、count、durationMs                             | IpcChangeFeed            |
| app.log.dropped                                       | warn         | count                                                 | 日志队列，恢复后汇总一次 |

04 §3 的 command instrument(skip_all,fields(...),err) 为默认错误最终边界；一个失败已由 command 自动记录时，job service/transport/UI 不再重复记同一错误。取消是正常标签结果，不输出 error；非 command 的启动/退出失败由其最终处理层记一次。用户通知与日志是两种渠道，但不能为每层异常重复 toast。

字段采用 allowlist：不写标题、正文、附件内容/名称、搜索词、用户绝对路径、SQL、cookie、token、TOTP、DPAPI 密文、备份凭据、含 query/fragment 的远端 URL。凭据整项删去或固定 `[redacted]`，不保留首尾片段。异常 source 在边界格式化前脱敏，日志事件名不拼用户输入。列表/导入逐条循环不记 info，进度走 Channel，不把 progress 刷入日志。

- **步骤**：1. runner MSVC 初始化并核对 cl/link。2. 三处版本+tag 严格一致。3. frozen-lockfile、check/test/clippy/fmt、构建、包结构与哈希验证。4. 成功后自动发布或手动选择此前成功的 tag 构建。5. 精确上传两个包，披露未执行人工场景，不需要独立审核或证据 secrets。
- **判据**：版本、构建来源/提交、哈希或包结构不匹配时失败；成功 workflow 使用 runner 编译器且 Release 为本轮 NSIS+portable；编译及自动检查通过即可发布。
- **陷阱**：本地 portable 与 runner 策略不能合并成「找到 cl 就行」；CLI 成功不构成隐藏的人工验收通过。

## 9. 设计裁决与原因

本节均为已确定设计，不保留待定分支；实施 API/版本可用性需按任务实际运行验证，不能据此文声称已验证。

| 编号 | 裁决                                                                    | 原因与归属                                                                   |
| ---- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Q1   | 进度用 IPC Channel，取消用 jobId；无全局 progress                       | 已按最新 02 §8/04 §7 修正初稿，调用隔离与退出可控；D3-4                      |
| Q2   | library-changed→library，载荷为本地 SyncResponse                        | 不再仅 notes；folders/tags/deletions/cursor 缺一不可，远端序列不可混入；D2-3 |
| Q3   | 备份语义/解包 payload hash 互通，不要求 ZIP 字节一致                    | 压缩/容器时间戳不同不是不兼容，双方向真实导入才是证据；D3-1/2                |
| Q4   | AppInfo 保持桌面局部；BackendSession 扩展本地 site 而不改 HTTP SiteInfo | 不污染 Worker 契约和共享领域 DTO；D2-2/5                                     |
| Q5   | 附件 stage→新对象发布→单 DB 事务→引用保护回收                           | FS/DB 不共事务，必须用崩溃恢复守住原子可见性；D3-2                           |
| Q6   | 取消提交前 rollback，提交临界区后返回真实终态                           | 不把已经成功导入的操作误报取消，也不把丢 Promise 当取消；D3-4                |
| Q7   | exe 旁 data 是唯一运行时根，窗口状态自行保存                            | WebView2 创建前必须指定缓存根，禁止 cwd/TEMP 回退；D2-5、D6-3                |
| Q8   | 退出等待共享编辑与本地提交，不等远端                                    | 保护最后按键且断网能退出；失败留窗，强制丢弃需用户明确选择；D6-3             |
| Q9   | clean 白名单保护所有 exe 旁 data，包括 target/debug 与 dist             | 当前整删 target 不安全，构建缓存目录中也可能有用户库；D6-4                   |
| Q10  | 本地强制 portable MSVC；GitHub 使用 runner MSVC                         | 复用现有工具链合同，不引入隐式本地 VS 回退；D6-4/6                           |
| Q11  | NSIS currentUser 与保留 data 是实现目标，需真实安装/升级/卸载验收       | 配置、退出码和脚本存在都不是数据安全证明；D6-5                               |
| Q12  | 日志凭据全删/固定掩码，不抄首尾 token 掩码                              | 04 的安全规范优先于参考项目实现；D2-6                                        |
| Q13  | 文件选择在 transfer command 内通过 Rust dialog 完成，JS 无任意路径参数  | 用户选取与实际打开同处可信宿主，避免伪造授权字符串；D3-4                     |

设计文档本轮已补齐；开发须按任务依赖完成后逐项执行行为验收，再由 03 记录实施状态。
