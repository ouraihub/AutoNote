# 39 预设服务商（对齐 Cherry）设计及开发规划

> 状态：已确认并实施（2026-10-17）。范围：Aether 通用能力 + AutoNote 预设列表；Web 与桌面同时生效。

## 1. 需求（用户确认）

- AutoNote 预设三个服务商：七牛云、硅基流动、Fenno。"获取密钥"链接换成用户的邀请链接。
- 预设不带密钥，由用户自己填写。
- 协议默认 OpenAI Chat，可在请求配置里切换（复用现有协议下拉）。
- 采用 Cherry 的方式（B）：首次打开时预设直接出现在列表里，默认关闭；用户删除后不再出现。
- 七牛云、硅基流动都用国内地址。
- 做成 Aether 通用能力：每个桌面程序可以预设自己的服务商。

## 2. Cherry 做法与取舍

Cherry 的预设目录在 `@cherrystudio/provider-registry`（66 个服务商）。`PresetProviderSeeder` 启动时写入只含身份信息的数据库行，地址在读取时从目录合并，只存差异。

我们只取其中三点：首次写入一次；用 `presetId` 记住来源；预设服务商不能删除，和 Cherry `ProviderService.delete` 拒绝删除预设行一样，界面也不显示删除。不做差异存储：预设写入后，名称、地址、协议、模型都可以随意改。不内置模型和价格："获取模型"会拉取实时列表。

## 3. 合同

```ts
// Aether ports（手写，非 DTO 生成）：每个程序自己传
interface ProviderPreset {
  id: string                 // 稳定 id，如 'qiniu'
  name: string
  baseUrl: string
  protocol: Protocol
  apiKeyUrl?: string         // "获取密钥"（邀请链接）
}
<ProvidersSettings presets={...} />
```

- DTO：`Provider.presetId: string | null`；`ProviderSave.presetId?: string` 只在新建时写入，之后不能修改。
- 存储：每个用户最多有一个服务商带某个 `presetId`。
  - 该预设已存在时，重复写入是空操作，后端返回当前列表，不报错，这样多标签页或多窗口同时打开也安全。
  - 已有同名服务商（不区分大小写）且它还没有 `presetId` 时，就把这个预设挂到它身上，不再另建一份。这样用户自己建的 `fenno` 也能拿到邀请链接。
  - 预设服务商不能删除：`remove` 返回 `conflict(preset_provider)`；行菜单和设置弹窗里都不显示"删除"，可以通过关闭开关停用。
- 界面：`ProvidersSettings` 加载列表后，对还没有对应服务商的预设逐个 `save`。
  - 写入时关闭、无密钥，带一条地址和协议都已填好的线路。
  - 列表行和密钥区显示"获取密钥"链接：按 `presetId` 找到对应预设，再取它的 `apiKeyUrl`。

## 5. 验收

- Rust：同一预设只写入一次；同名服务商接管预设；预设服务商删除被拒绝；`presetId` 之后不能修改。
- Web：同上，并且不同用户之间互不影响。
- 界面：首次加载写入缺少的预设；"获取密钥"链接指向预设的 `apiKeyUrl`；预设服务商的行菜单里没有"删除"。
- 真实环境：
  - Web 与桌面安装包首次打开设置，看到三个关闭状态的预设，并且有"获取密钥"链接。
  - 预设的行菜单里没有"删除"；重启后预设仍在。
  - 已有的同名 Fenno 接管预设：不新增一份，原有配置不变，并显示邀请链接。
