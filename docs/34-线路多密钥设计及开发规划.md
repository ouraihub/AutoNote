# 34 线路多密钥（Cherry API 密钥管理）设计及开发规划

> 范围：Aether（`aether-support`、`aether-providers`、`aether-chat`、`tauri-plugin-aether`、`packages/ui`）+ AutoNote Web（`web/src/worker`、`web/src/client/backend/ports/kit.ts`）。桌面与 Web 同一套 UI、同一套行为。
> 原则：新项目，不做旧数据迁移，旧密钥作废需重新填写；不留兼容字段与别名。

## 1. Cherry 怎么做的（源码事实，根 `E:/docs/AI申请/AI安装配置教程/ai/cherry-studio/src`）

| 点 | 位置 | 行为 |
| --- | --- | --- |
| 数据 | `shared/data/types/provider.ts:61-70` | `ApiKeyEntry { id, key, label?, isEnabled }`，挂在服务商上 |
| 主密钥 | `renderer/.../ConnectionSettings/ApiKey.tsx:81` | 第一个启用的，否则第一个 |
| 密钥行 | 同上 `:110-189` | 文字区是按钮（点开密钥管理）：打码主密钥 + `+N`；悬停/聚焦出现 复制、编辑、删除（删除仅 1 个密钥时）；眼睛常驻；行外 🔑（密钥管理）+ 检测 |
| 无密钥 | 同上 `:192-211` | “添加 API 密钥”按钮 + 🔑 |
| 密钥管理 | `ProviderApiKeyListDrawer.tsx` | 标题“API 密钥管理”；行 = 标签/打码（点击复制）+ 复制、编辑、删除、启用开关；编辑行 = 标签 + 密钥两个输入，Enter 保存 Esc 取消；底部整宽“添加 API 密钥”；页脚“{启用}/{总数} 已启用”；空/重复校验；每个动作立即保存；删除不确认 |
| 轮换 | `main/data/services/ProviderService.ts:674-712` | 只在启用的密钥中 round-robin；全部停用 = 无密钥；**失败不切换** |
| 检测 | `ModelList/ProviderModelCheck.tsx`、`ModelCheckDialog.tsx`、`ApiKeyCheckResults.tsx` | 范围“单个/全部”密钥；结果按密钥列出 通过/失败 + 原因，行内开关可停用坏密钥 |
| 新服务商 | 服务商创建即入库，没有地址也能加密钥 | 密钥管理始终可用 |

## 2. 决策

| 问题 | 决定 |
| --- | --- |
| 密钥挂在哪 | **线路**（endpoint）。单线路时界面与 Cherry 一致 |
| 字段 | `id, label, enabled, position` + 密文；每线路 ≤ 16 个，标签 ≤ 40 字符，密钥 ≤ 4096 字节 |
| 保存 | 每个动作立即调用独立接口；密钥不进 `ProviderSave`、不进草稿 |
| 新线路 | 与 Cherry 一致：线路创建即入库（地址允许为空），🔑 立即可用；地址为空时检测/同步禁用，聊天报配置错误 |
| 主密钥 | 第一个启用的，否则第一个 |
| 轮换 | 启用的密钥按 `position` round-robin；游标在进程内存（`endpointId → 下次起点`），重启从头 |
| **失败切换（超出 Cherry）** | 一次请求按轮换顺序依次尝试启用的密钥：上游在首字节前返回 **401/403/429** 时换下一个；其他错误、或已开始输出、或已试完，直接报错。聊天每一轮、绘图、同步模型都适用 |
| 全部停用 / 无密钥 | 等同无密钥（`missing_key`，回环地址除外） |
| 检测 | 0~1 个启用密钥：沿用现有单行结果；≥ 2 个：逐个启用密钥探测，按密钥列出结果（Cherry “全部”范围），行内开关可停用 |
| 删除 | 对话框内不确认；密钥行（仅 1 个时出现）沿用现有确认框 |
| 重复 | 后端解出同线路其他密钥逐一比较，重复 → `bad_request(field "apiKey", reason "duplicate")` |
| 查看/复制 | 按密钥 id；Web 需当前密码，桌面直接解 |

不做：检测里的模型选择/并发/超时设置、拖拽排序、密钥同步备份、逗号批量导入。

## 3. 接口契约（三端共同遵守）

### 3.1 DTO（Rust `crates/aether-providers/src/dto.rs` 为准，`pnpm kit:dto` 生成 `packages/ui/src/ports/generated/`）

```ts
type EndpointKey = { id: string; label: string; enabled: boolean; masked: string | null; readable: boolean }
type Endpoint = { id; slug; baseUrl; protocol; keys: EndpointKey[]; probeUrl; models }   // 删 hasKey/keyMasked/keyReadable
type EndpointSave = { id?; slug; baseUrl; protocol; models }                            // 删 apiKey；baseUrl 允许 ''
type EndpointKeySave = { endpointId: string; id?: string; key?: string; label?: string; enabled?: boolean }
type ProbeTarget =
  | { kind: 'saved'; endpointId: string }
  | { kind: 'draft'; baseUrl: string; protocol: Protocol; endpointId?: string; keyId?: string } // 删 apiKey
```

- `keys` 按 `position, id` 排序；`masked = mask_secret(明文)`，解不开 `masked=null, readable=false`。
- `EndpointKeySave`：无 `id` = 新增（`key` 必填，`enabled` 默认 true，`label` 默认 ''）；有 `id` = 修改，省略字段保持不变。
- `ProbeTarget.draft.keyId`：只用这一个密钥（必须属于 `endpointId`，否则 `not_found("key")`）；省略则按 §3.4 轮换 + 失败切换。

### 3.2 错误

| 情况 | 错误 |
| --- | --- |
| 线路不存在 / 不属于当前用户 | `not_found("endpoint")` |
| 密钥不存在 / 不属于该线路 | `not_found("key")` |
| 新增缺 `key`，或 `key` trim 后为空 | `bad_request("apiKey", "empty")` |
| `key` > 4096 字节 | `bad_request("apiKey", "too_long")` |
| 与同线路其他密钥明文相同 | `bad_request("apiKey", "duplicate")` |
| `label` trim 后 > 40 字符 | `bad_request("label", "too_long")` |
| 新增时已有 16 个 | `bad_request("keys", "too_many")` |
| 选中的密钥解不开 | `needs_config("key_unreadable")` |

`key`、`label` 一律 trim 后保存。

### 3.3 Port（`packages/ui/src/ports/contract.ts` `ProvidersPort`）

```ts
saveKey(input: EndpointKeySave): Promise<Provider[]>
removeKey(endpointId: string, keyId: string): Promise<Provider[]>
revealKey(keyId: string, currentPassword?: string | null): Promise<string>   // 参数由 endpointId 改为 keyId
```

| 宿主 | saveKey | removeKey | revealKey |
| --- | --- | --- | --- |
| 桌面 `packages/ui/src/tauri/index.ts` | `providers_key_save {input}` | `providers_key_delete {endpointId, keyId}` | `providers_key_reveal {keyId}` |
| Web `web/src/client/backend/ports/kit.ts` | `PUT /api/ai/kit/endpoint-keys` body=input | `DELETE /api/ai/kit/endpoint-keys/:keyId` body `{endpointId}` | `POST /api/ai/kit/endpoint-keys/:keyId/reveal` body `{currentPassword}` |
| `packages/ui/src/ports/fake.ts` | `resolve([])` | `resolve([])` | reject（不变） |

Web 旧路由 `POST /api/ai/endpoints/:id/key`（`web/src/worker/routes/ai.ts`）删除。

### 3.4 选钥与失败切换（后端，两端同语义）

```text
keys(endpointId) = 该线路 enabled=1 的密钥，按 position, id；逐个解密，任一解不开 → needs_config("key_unreadable")
n = len(keys); n == 0 → []
start = cursor[endpointId] % n; cursor[endpointId] = (start + 1) % n; 返回 keys 从 start 起循环一圈

发请求（聊天每一轮 / 绘图 / 探测）:
  candidates = keys 为空 ? [无密钥] : keys
  for i, key in candidates:
    结果 = 用 key 发请求直到拿到首字节或错误
    成功 → 继续流式读取（之后的错误不再换钥）
    上游 HTTP 401/403/429 且 i+1 < len → 下一个
    其他 → 返回错误
```

- Rust：`aether_support::Connection.api_key: Option<..>` 改为 `api_keys: Vec<Zeroizing<String>>`（已按上面顺序排好；空 = 无密钥）。`Debug` 打印个数，不打印内容。脱敏 `known` = 全部密钥。游标：`Store` 加 `cursors: Mutex<HashMap<String, usize>>`（同 `aether-search/src/lib.rs` L782-791）。
- Web：`Connection.apiKey: string | null` 改为 `apiKeys: string[]`；游标模块级 `WeakMap<D1Database, Map<string, number>>`，键 `JSON.stringify([userId, endpointId])`（同 `web/src/worker/ai/search.ts` L42、L97-101）。
- 探测失败切换条件：`ProbeErrorKind::Unauthorized | RateLimited`。
- “无密钥只允许回环地址”（`aether-chat/src/validate.rs` L125-129、Web `runs.ts` L255 附近）改为判断 `api_keys` 为空。

### 3.5 空地址

- 保存：`baseUrl` 允许 `''`；非空时仍须 `http(s)://`、≤ 2048 字节。
- `resolve`（聊天/绘图取线路）遇空地址 → `needs_config("missing_url")`；探测空地址 → `bad_request("url","invalid_url")`（UI 已禁用按钮）。
- `modelOptions` 不过滤空地址线路（模型来自同步，空地址时本来就没有模型）。

## 4. 存储（不迁移旧数据）

桌面 `aether-providers/src/store.rs`，`Store::open` 的 `steps` 追加 **v5**：

```sql
ALTER TABLE endpoints DROP COLUMN key_ciphertext;
CREATE TABLE endpoint_keys (
  id TEXT PRIMARY KEY,
  endpoint_id TEXT NOT NULL REFERENCES endpoints(id) ON DELETE CASCADE,
  label TEXT NOT NULL DEFAULT '', enabled INTEGER NOT NULL DEFAULT 1,
  key_ciphertext BLOB NOT NULL, position INTEGER NOT NULL
);
CREATE INDEX idx_endpoint_keys ON endpoint_keys(endpoint_id, position, id);
```

删线路 / 删服务商 / 删密钥 / 改密钥：先把要丢弃的 `key_ciphertext` 收进 `stale`，事务提交后 `forget_all`（现有写法）。

Web `web/src/worker/db/schema.ts`：

- `SCHEMA_STATEMENTS`：`ai_endpoints` 去掉 `key_ciphertext TEXT,`；新增
  ```sql
  CREATE TABLE IF NOT EXISTS ai_endpoint_keys (
    id TEXT PRIMARY KEY, user_id TEXT NOT NULL, endpoint_id TEXT NOT NULL,
    label TEXT NOT NULL DEFAULT '', enabled INTEGER NOT NULL DEFAULT 1,
    key_ciphertext TEXT NOT NULL, position INTEGER NOT NULL
  )
  CREATE INDEX IF NOT EXISTS idx_ai_endpoint_keys ON ai_endpoint_keys(user_id, endpoint_id, position, id)
  ```
- 迁移 **v23**（重建表，新库旧库都成立，同 v20 写法）：建 `ai_endpoints_v23`（无密钥列）→ `INSERT ... SELECT id, user_id, provider_id, slug, base_url, protocol, position FROM ai_endpoints` → `DROP TABLE ai_endpoints` → `RENAME` → 重建 `idx_ai_endpoints_user`。
- `REQUIRED_COLUMNS`：`ai_endpoints` 去 `key_ciphertext`；加 `ai_endpoint_keys: ['id','user_id','endpoint_id','label','enabled','key_ciphertext','position']`；`REQUIRED_TABLES` 加 `ai_endpoint_keys`；索引清单加 `idx_ai_endpoint_keys`。
- 加密：`encryptAiKey(env, keyId, key)` / `decryptAiKey(env, keyId, cipher)`（`web/src/worker/lib/crypto.ts`，参数名改 `scopeId`，作用域串不变）。
- 所有删 `ai_endpoints` 的语句旁边补删 `ai_endpoint_keys`（`providers.ts` 保存删线路、删服务商）。

## 5. UI（`packages/ui/src/providers/`）

### 5.1 密钥行 `SecretInput.svelte`

Props：`id`、`endpoint: Endpoint`、`onchanged(providers: Provider[])`。

```
有密钥： [ 标签? sk-y****nHP5  +1      (悬停/聚焦: ⧉ ✎ 🗑*) 👁 ]  [🔑]  [检测]
无密钥： [ 输入 API 密钥 ……………………………………… ]  [🔑]  [检测]
```

- 主密钥 = 第一个 `enabled`，否则 `keys[0]`；显示 `masked` 中段压成 `****`；不可读显示 `providers.key_unreadable`。
- 文字区是 `<button>`：点击打开密钥管理（`aria-haspopup="dialog"`）。`+N`：`keys.length > 1`。
- 悬停/聚焦动作（保留现有 `group-hover/key` 写法）：复制（主密钥；未显示时先 reveal）、编辑（打开密钥管理，主密钥进入编辑行）、删除（仅 `keys.length === 1`，现有确认框）。
- 眼睛：显示/隐藏主密钥明文（Web 先问当前密码，保留现有行内密码框）。
- 无密钥：密码输入框；失焦或 Enter 且非空 → `saveKey({ endpointId, key })`，成功清空；Escape 清空。
- 🔑：`variant="outline" size="icon"`，`KeyRoundIcon`，`title`/`aria-label` = `providers.keys_manage`。
- `EndpointPanel.svelte` 把 🔑 放在密钥行与检测之间；检测/同步模型在地址为空时禁用（现有）。
- `ProvidersSettings.svelte` 状态点：启用但 `endpoints` 为空、或任一线路没有启用的可读密钥 → warning。

### 5.2 密钥管理 `EndpointKeysDialog.svelte`（新；`Dialog`，`sm:max-w-md`，结构同 `ModelSettingsDialog.svelte`）

- Props：`open`（bindable）、`endpoint: Endpoint`、`editKeyId: string | null`（打开即编辑该行）、`onchanged`。
- 标题 `providers.keys_manage`，说明 `providers.keys_desc`。
- 行：有标签则上行 `text-sm` 标签；下行 `font-mono text-xs text-muted-foreground` 打码（点击 = 复制）；右侧 复制、编辑、删除（不确认）、`Switch size="sm"`（`aria-label` = `providers.keys_enable_for {name}`，name = 标签或打码）。不可读行：复制禁用。
- 复制需要明文：Web 第一次复制时对话框顶部出现当前密码框，回车后执行，本次打开内复用，关闭即清空；桌面直接复制。
- 编辑行：标签输入（占位 `providers.keys_label`）+ 密钥输入（`type="password"`，自动聚焦；新增占位 `providers.key_placeholder`，编辑占位 `providers.keys_keep`）+ ✓ / ✕；Enter 保存、Escape 取消。编辑时密钥留空 = 只改标签。
- 前端预检：新增时密钥为空 → toast `providers.keys_err_empty`，不请求。后端 `bad_request` 按 reason 映射：`duplicate`/`too_many`/`too_long`(label)/其他 → `providers.keys_err_duplicate`/`keys_err_too_many`/`keys_err_label`/`keys_save_failed`。
- 同一时刻一个请求，进行中全部按钮禁用；失败保留编辑行。
- 空列表 `providers.keys_empty`；底部整宽 secondary“+ `providers.keys_add`”（有编辑行或满 16 时禁用）；页脚 `providers.keys_enabled_count {enabled} {total}`。
- 每次成功把返回的 `Provider[]` 交给 `onchanged`；`ProvidersSettings` 用它替换 `providers`，并只把对应线路草稿的 `saved` 换成新 `Endpoint`，然后 `notifyChanged()`。

### 5.3 检测结果

- `ProvidersSettings.runProbe`：线路启用密钥 ≥ 2 时，对每个启用密钥串行 `probe({ kind:'draft', baseUrl, protocol, endpointId, keyId })`，结果存成 `[{ keyId, result }]`；否则维持现状单次探测。
- `EndpointPanel` 检测状态区：多密钥结果按行显示 `✓/✕ 标签或打码 — 可用 N 个模型 / 错误文案` + `Switch size="sm"`（`saveKey({ endpointId, id, enabled })`）。

### 5.4 删除

- `draft.ts`：`EndpointDraft.key`、`toSave` 的 `apiKey`、`probeTarget` 的 `apiKey`、`adopt` 的 key 逻辑；`savable` 不再过滤空地址线路（地址只校验格式：非空且非法时不保存）。
- `EndpointPanel.svelte`：`pending`/`oncommit` 密钥部分。
- Web：`ProviderSaveSchema`/`ProbeTargetSchema` 的 `apiKey`、`validateSave` 的 apiKey 校验、`saveProvider` 的三态、`routes/ai.ts` 旧 reveal 路由。

## 7. 验收（Web 与桌面各一遍；上游用本地回环服务，看收到的 Authorization）

1. 新建服务商：不填地址即可点 🔑 添加密钥；密钥行显示打码，无 `+N`。
2. 添加第二个（带标签）→ 立即保存，`+1`，页脚“2 / 2 已启用”；重复 → “API 密钥已存在”；空 → “API 密钥不能为空”且不发请求。
3. 编辑：只改标签不动密钥；改密钥后打码变化。关掉第一个 → 主密钥换成第二个，“1 / 2 已启用”。
4. 轮换：两个启用密钥，连发 4 次聊天，上游依次收到 k1,k2,k1,k2。
5. 失败切换：上游对 k1 返回 401（或 429），聊天仍成功，上游先后收到 k1、k2；两个都 401 → 报错显示上游原因。
6. 检测：多密钥时按密钥列出结果，坏密钥 ✕ 并显示原因，可在结果行直接停用。
7. 复制/眼睛：Web 需当前密码，桌面直接；复制内容为明文。
8. 删除：对话框里删不确认；只剩 1 个时密钥行悬停出现删除，确认后变为输入框；全部停用后聊天报缺密钥。
9. 刷新 / 重启后状态保持；浅色/深色、320/375/414/768 px 无横向溢出；Tab 可到每个按钮，Esc 关闭对话框。
